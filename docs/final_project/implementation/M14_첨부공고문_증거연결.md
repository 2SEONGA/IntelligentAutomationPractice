# M14 첨부 공고문 증거 연결

작성일: 2026-11-16  
상태: 코드 연결 및 정적 확인 완료. 실제 공고문 포함 실행과 G2B 첨부 판본 확인은 남아 있음.

## 요약

- **한 일:** 다운로드한 공고문 PDF의 출처 sidecar(URL·SHA-256)를 남기고, 공고문을 LangGraph에서 별도 추출해 제안서 제출기한 인용과 페이지 링크를 검토 화면에 연결했다.
- **결과:** 사용자 확인: 공고문 판본 문제 없음, 추출 인용·페이지 링크 정상.
- **남은 일:** 변경이력 기반 판본 판별, 수동 업로드 경로 sidecar.

## 목표

나라장터 공고 API가 제공하는 첨부 링크를 실제 내려받은 원문과 연결하고, 해당 PDF에서 확인한 제안서 제출기한을 페이지 인용과 함께 T1.5 검토 화면에 표시한다. 입찰 마감(`bidClseDt`)과 제안서 제출기한은 서로 다른 일정으로 유지한다.

## 현재 확인한 구조

- `src/bid_review/web/notices.py`의 `fetch_attachments()`는 기존 공고 수집 저장소의 첨부를 내려받아 실행 폴더의 `notice.pdf`와 `rfp.pdf`로 저장한다.
- `src/bid_review/web/app.py`의 공고 시작 경로는 공고문 PDF를 기존 Crew 실행에 넘긴다.
- 담당자 핵심정보 검토 경로(`/api/runs/{run_id}/core-review`)는 별도로 `run_bid_review()`를 호출하지만 RFP 경로만 전달한다.
- `src/bid_review/rag/workflow.py`의 LangGraph는 RFP를 T1 추출한 뒤 G2B API를 조회하고 T1.5를 실행한다. 공고문 PDF 텍스트·페이지 근거는 현재 그래프 State에 포함되지 않는다.
- 검토 화면의 기존 페이지 링크는 RFP PDF만 가리키므로, 공고문 인용을 추가하려면 파일 제공 경로와 링크 대상을 함께 확장해야 한다.
- 따라서 첨부 URL 표시와 파일 다운로드 기능은 일부 존재하지만, 이를 제안서 기한 검증 근거로 사용하는 것은 아직 구현되지 않았다.

## 이번 작업

- `src/bid_review/web/app.py`에서 기존 공고문 PDF 다운로드가 성공한 경우 `notice_attachment.json` sidecar를 실행 폴더에 작성한다.
- sidecar에는 공고 식별자/차수, 첨부명, 첨부 URL, 다운로드 시각, 로컬 파일명, SHA-256을 남긴다.
- sidecar에 이 출처가 기존 공고 수집 저장소의 URL임을 표시해, 이번 실행에서 API를 실시간 재조회한 것으로 오인하지 않게 했다.
- 이번 변경은 기존 웹 공고 수집 경로에만 적용된다. 수동 업로드 파일이나 LangGraph에서 직접 API를 조회한 첨부에는 아직 적용되지 않는다.
- `src/bid_review/web/app.py`: 핵심정보 검토 실행 시 동일 실행 폴더의 `notice.pdf`를 LangGraph에 넘긴다.
- `src/bid_review/rag/workflow.py`: 공고문 PDF가 있으면 `document_kind="notice_pdf"`로 별도 추출하고, 파일이 없음/추출을 요청하지 않음을 State에 구분해 보존한다.
- `src/bid_review/rag/verification.py`: 공고문의 `proposal_deadline` 후보를 RFP 후보와 함께 비교한다. 공고문에서 추출한 인용은 자동 확정하지 않고 담당자 확인 상태로 둔다. 서로 다른 날짜 후보가 있으면 기존 충돌 판정을 적용한다. 입찰 마감 API 필드는 계속 별도로 유지한다.
- `src/bid_review/web/runs.py`, `web/src/components/PageLink.tsx`, `web/src/components/tabs/CoreReviewTab.tsx`: 검토 API에서 case-local `notice.pdf`를 제공하고, 인용의 `source_path`에 따라 해당 PDF의 페이지로 이동한다. 공고문 추출 상태도 화면에 표시한다.

## 구현 범위 및 완료 기준

1. 실행 폴더의 공고문 PDF와 첨부 메타데이터(파일명, 원 URL, 공고번호·차수, 다운로드 시각, SHA-256)를 연결해 보존한다. 기존 수집 경로는 부분 구현했다.
2. core-review에서 같은 실행의 공고문 PDF 경로를 LangGraph에 전달한다. 구현 완료. 파일이 없거나 제공되지 않은 경우 상태를 별도로 표시한다.
3. 공고문 PDF를 페이지 단위로 추출하고 `proposal_deadline` 후보 및 원문 인용을 T1.5에 전달한다. 코드 연결 완료. 추출 날짜의 의미/시각은 사람이 확인해야 한다.
4. RFP 후보와 공고문 후보를 함께 표시하고 충돌은 담당자 검토로 보낸다. 코드 연결 완료. 실제 사례 결과 확인은 남아 있다.
5. `bidClseDt`는 API 입찰 마감으로 별도 표시하며 proposal deadline의 대체 근거로 사용하지 않는다.
6. 검토 화면에서 출처 문서명, 페이지, 인용문, 원문 PDF 접근을 확인할 수 있다.

## 미해결/제약

- 현재 실행환경에서 G2B 실시간 API 호출이 `ConnectionError`로 끝나 실제 첨부 파일과 판본을 확인하지 못했다. API 연결 가능 환경에서 내려받기·해시 검증은 별도로 확인해야 한다.
- 스캔 PDF의 OCR이 필요한지, API 첨부가 정정 공고의 최신 판본인지 판별하는 규칙은 확인이 필요하다. 불확실한 경우 자동 확정하지 않고 담당자 검토로 남긴다.
- 이번 확인: Python 수정 파일 AST 구문 분석 성공, 웹 `npm run build` 성공. 테스트 스위트는 실행하지 않았다.
- 사용자 확인: 공고문 추출 결과와 PDF 페이지 링크가 맞다. 이 확인은 citation 표시/링크를 승인한 것이고, G2B에서 내려온 첨부가 최신 또는 해당 차수의 공식 판본인지는 별도 확인 대상이다.
- 사용자가 화면을 확인할 수 있도록 `M14_공고문_검증_화면_미리보기.html`을 추가했다. 이는 실제 실행 결과가 아닌 정적 UI 미리보기이며, 현재 확인된 미완료 상태를 그대로 표시한다.
- `.venv/bin/python run_web.py` 실행 시 환경에서 `127.0.0.1:8000` bind가 `operation not permitted`로 거부되어 실제 웹앱을 열지 못했다. OS의 `open` 명령도 HTML을 처리할 브라우저 앱이 없어 실패했다.

## 다음 단계

### G2B 첨부 판본 확인 절차

1. 공고번호 `R26BK01762350`, 차수 `000`을 키로 나라장터 공고 상세정보를 다시 조회한다. API 응답에서 공고번호·차수·공고명·공고 상세 URL이 기대한 건인지 확인하고 raw 응답(JSON)과 조회 시각을 함께 보존한다.
2. 같은 공식 입찰공고정보서비스의 **입찰공고목록 정보에 대한 첨부파일정보조회**를 별도로 조회한다. 용역 공고이므로 `bsnsDivCd=5`를 사용하고, 조회구분을 공고번호(`inqryDiv=2`)로 두어 공고번호와 차수를 지정한다. 반환된 첨부 문서 구분·파일명·첨부 URL을 공고 상세 페이지의 첨부 목록과 대조한다. 조달청 명세에는 이 조회가 첨부 문서 구분명, 파일명, URL을 제공한다고 나와 있다.
3. 응답 URL에서 PDF를 내려받아 원본 바이트의 SHA-256, 파일명, 다운로드 시각을 기록한다. 기존 `notice.pdf`와 hash가 같으면 바이트가 동일하다는 뜻이다. hash가 다르면 최신/정본을 뜻한다고 단정하지 않고, 두 파일을 모두 보존해 차이를 본다.
4. **용역변경이력조회**에서 해당 공고번호의 변경 차수와 변경항목/전후값을 확인한다. 조달청 명세상 이력에는 공고 차수와 공고서·규격서 변경이 포함된다. 공고 차수 번호가 크다는 이유만으로 해당 PDF를 최신판이라고 정하지 않는다.
5. PDF 본문에서 공고번호, 사업명, 발주기관, 공고/정정 일자 및 표지의 판본 단서를 확인한다. `proposal_deadline` 인용 페이지의 내용이 해당 차수 공고와 일치하는지 검토하고 RFP의 “입찰공고문 참조”와 날짜·시각을 비교한다. 값이 다르거나 문서가 다른 공고를 가리키면 T1.5 충돌/담당자 검토로 남긴다.
6. 실행 기록에는 공고번호·차수, 공고 상세 URL, API operation 및 조회 시각, 첨부 문서 구분·이름·URL, 로컬 파일 SHA-256, 변경이력 요약, 확인한 PDF 페이지를 저장한다. API URL 및 판본 근거가 확보되기 전에는 `notice.pdf`를 최신 G2B 첨부로 표시하지 않는다.

공식 근거: [조달청 나라장터 입찰공고정보서비스 명세](https://www.data.go.kr/data/15129394/openapi.do)는 첨부파일정보조회가 첨부 문서 구분·파일명·URL을 반환하고 공고번호·차수로 조회할 수 있다고 명시한다. 같은 명세의 용역변경이력조회에는 공고 차수 및 공고서/규격서 변경항목이 포함된다. 현재 작업환경은 앞서 실시간 API 요청이 `ConnectionError`였으므로 이 절차에 따른 실제 판본 대조는 미완료다.

현재 정적 미리보기는 화면 배치와 상태를 보여준다. 실제 첨부 판본 확인은 네트워크가 허용되는 환경에서 위 절차를 실행해야 한다.
