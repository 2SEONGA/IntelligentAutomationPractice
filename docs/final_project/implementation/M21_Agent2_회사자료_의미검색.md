# M21 Agent 2 회사 자료 의미 검색

작성일: 2026-11-17  
상태: 완료 (상수도관 T2 라이브 실행으로 이전 결과와 비교). 행정 조항에 붙는 후보 잡음은 남음.

## 요약

- **한 일:** T2 회사 자료 RAG(M10)에 M4의 OpenAI 임베딩을 적용했다. 요구사항 전체를 한 번에 임베딩하고, 키워드(FTS5) 후보와 의미 검색 상위 후보를 합친 뒤 유사도 0.35 이상만 유사도 순으로 최대 3건 남긴다. API를 쓸 수 없으면 기존 키워드 후보로 돌아간다.
- **결과:** 상수도관 T2에서 전체 후보는 46→41건으로 줄었고, 여러 요구사항에 반복되던 인증 레코드 잡음(CAP-CERT-001)은 9→2회로 줄었다(보안·품질 요구사항에만 남음). 회사에 해당 실적이 없는 드론·AI 영상 요구사항은 억지 후보 없이 비게 됐다. 적합도는 50.0%로 변하지 않았다(후보는 점수에 합산하지 않음). 테스트 16개 파일, 웹 빌드 통과.
- **남은 일:** 보안서약·지식재산권 같은 행정 조항에도 실적 레코드가 0.36~0.40으로 붙어 임계값으로는 걸러지지 않는다. T1이 행정 조항을 요구사항으로 뽑는 문제와 회사 자료가 11건뿐인 데이터 한계가 원인이다. 정답 라벨 평가와 행정 조항 검색 제외 규칙이 후속 과제다.

## 변경 내용

- `src/bid_review/rag/company_retriever.py`
  - `company_record_metadata()`: 레코드별 메타데이터 생성을 FTS 색인과 같은 형식으로 분리했다(대상 법인 ㈜아이티센엔텍 확인 포함).
  - `company_semantic_scores(queries)`: 레코드 벡터를 `outputs/rag/company_embeddings.npy`에 캐시하고, 회사 JSON의 SHA-256이 바뀌면 다시 계산한다. 질의는 한 번의 API 호출로 묶는다. 실패하면 `SemanticUnavailable`을 내며, 키와 응답 본문은 남기지 않는다.
  - `clean_requirement_query()`: RFP 표 머리말("요구사항 고유번호 |", "표 행:")을 지운다.
  - 레코드 임베딩 텍스트는 제목·키워드·발췌만 쓴다.
- `src/bid_review/rag/workflow.py` (`t2_company_rag_retrieval`): 요구사항별 자료 유형 제한(실적/인증/재무/사업역량)과 인력 요구사항 제외 규칙은 그대로 둔다. 후보 선택만 바꿨다. `company_retrieval_note`에는 사용한 검색 방식(또는 의미 검색 실패 사유)을 기록한다.
- `src/bid_review/models.py`: `RetrievedCompanyEvidenceCandidate.retrieval_method`에 "키워드+의미 검색"과 "의미 검색"을 추가하고 `semantic_score`를 넣었다.
- `web/src/components/tabs/CapabilityTab.tsx`: 후보마다 검색 방식과 유사도를 표시한다.
- `tests/test_semantic.py`: 캐시 재사용, 회사 JSON 변경 시 재계산, API 실패 시 키 미노출, 질의 정리를 검증한다.
