## 2. T3 유사 사업 검색 (M42)

- **재색인:** 사업 수 102건 → 110건, 프로필을 다시 확인해야 하는 사업 12건 → 4건, 낙찰 정보 연결 22건은 그대로. 비용 약 1센트.
- **임계값 관리:** 전에는 코드 안에 숫자로 박혀 있었는데, 이제 `config/settings.yaml`의 `min_similarity: 0.70`에서 읽는다. **값은 0.70 그대로다.**
- **판정표:** 시연 3건 × 상위 10건 = 30행. 담당자 요청으로 AI(Claude)가 대신 판정했고, "담당자 검토 전"이라고 판정표에 적어 두었다.

| 기준 | 정밀도 | 재현율 | F1 |
|---|---:|---:|---:|
| 유사도 0.70 (현재) | 0.458 | 0.846 | 0.595 |
| 유사도 0.80 / 0.90 | 1.000 | 0.154 | 0.267 |
| LLM 재정렬 1점 이상 (실험) | 0.867 | 1.000 | 0.929 |

- 유사도 점수만으로는 분야를 가르지 못한다. 예를 들어 상수도관 시연에서는 상위 10건 중 9건이 관련 없는 사업이었다.
- 그래서 **0.70은 유지하고, 재정렬을 추가하는 안**을 제안해 두었다. 다만 정답을 AI가 판정했기 때문에 재정렬 성능이 부풀려졌을 수 있다. 운영에 넣는 것은 담당자가 판정을 확인하고 승인한 뒤에 한다.

## 3. 성능·재현성 (M43)

- 문서 쪽 추출 결과를 캐시에 두고 다시 쓴다. 같은 PDF를 T1과 T3가 따로 읽던 것을 한 번만 읽게 했다.
- 임베딩 결과를 SQLite 캐시에 저장한다. 같은 문장은 OpenAI를 다시 부르지 않는다.
- 결과:
  - 5건을 차례로 실행하는 데 걸린 시간: **65.0초 → 52.7초 (18.9% 단축)**, 결과는 그대로.
  - T3에서 PDF를 다시 읽는 시간: 14.5초 → 0.08초
- Windows 호환:
  - 파일 잠금을 `fcntl` 대신 `msvcrt`로 바꿨다.
  - 테스트와 스크립트에서 UTF-8을 명시해 cp949 인코딩 오류를 없앴다.
