# M31 HWP·HWPX 제안요청서 처리 (Agent 3)

작성일: 2026-11-18  
상태: 완료 (라이브 80회 조회로 확인, 재색인)

## 요약

- **한 일:** Agent 3 과거 RFP 수집이 PDF 제안요청서만 받던 것을 HWP 5.0·HWPX도 받도록 고쳤다. 본문 추출기 `src/bid_review/hwp_text.py`는 표준 라이브러리만 쓴다(`olefile` 설치는 권한에서 막힘). M30에서 "PDF 없음"으로 기록한 752건은 다음 실행에서 다시 조회한다.
- **계기:** M30에서 첨부 조회 800회 중 752회(94%)가 "PDF 제안요청서 없음"이었다. 실제 공고함 첨부를 세어 보니 이름에 제안요청·과업이 들어간 첨부 2,279건 중 HWPX 1,118 · HWP 907 · PDF 254건이었다.
- **결과:** 라이브 80회 조회로 24건(HWP 18 · HWPX 6)을 새로 받았다. 저장률이 6%에서 30%로 올랐다. 과거 RFP 128 → 152건, 색인 사업 90 → 112건, 낙찰 연결 17 → 22건. 세 시연 공고의 유사 사업 상위 결과는 M30과 같다. 백엔드 테스트 17개 파일 통과.
- **남은 일:** 남은 "PDF 없음" 기록 재조회와 200건까지 이어받기(`scripts/build_past_projects.py`, 할당량 초기화 후). HWP 프로필 일부는 목차·계약 조항으로 시작한다(한계 참고).

## 라이브 확인 (2026-11-18)

- 실제 RFP 두 건으로 추출을 먼저 확인했다(공고함 첨부 URL에서 직접 받아 API 할당량은 쓰지 않음). 출연연 사이버보안 관제 HWP에서 79,870자, 해양수산과학기술진흥원 유지관리 HWPX에서 96,607자가 나왔다. 프로필은 목차를 건너뛰고 "사업 개요"부터 시작한다.

## 한계

- 프로필은 첫 "사업 개요/목적/범위" 제목부터 자른다. HWP는 쪽 번호가 없는 목차가 많아 일부 프로필이 제목 목록으로 시작한다(예: 경북도청신도시 스마트도시). 제안요청서에 계약 조항이 먼저 나오면 그 부분부터 들어가기도 한다(예: 새마을금고 계정계). 유사도 영향은 담당자 평가(M25 방식)로 확인해야 한다.
- 웹앱 공고 검토(T1)는 여전히 PDF 제안요청서만 쓴다. HWP를 T1에 넣으려면 쪽 번호 인용 체계부터 바꿔야 한다.
- 표 안 글자는 문단 순서대로 이어 붙인다. 표 구조(행·열)는 남지 않는다.
- 공개 저장소에 나라장터 공개 첨부(HWP·HWPX)가 그대로 올라간다. PDF와 같은 공개 공고 자료다.
