# M23 Agent 3 과거 공공사업 유사 검색

작성일: 2026-11-17  
상태: 완료 (라이브 수집·색인, 세 공고 LangGraph 실행). 수집 범위는 기본값이며 넓힐 수 있음.

## 요약

- **한 일:** 최근 나라장터 ICT 용역 공고의 제안요청서 PDF를 공식 첨부 API로 모아 사업 프로필(공고명·수요기관·사업 개요/목적/범위)을 만들고, OpenAI 임베딩으로 현재 RFP와 비슷한 과거 사업을 찾는 Agent 3 노드를 LangGraph의 T2 뒤에 붙였다. 낙찰자·낙찰금액은 공고번호가 일치할 때만 붙인다.
- **결과:** 공고 77건을 사업 63건으로 묶었고, 이 중 17건에 낙찰 결과를 연결했다. 통합정보시스템은 대학 학사시스템 사업(대신대 0.834, 동강대 0.792)이, CDW는 "조선대병원 거점병원 통합CDW 구축"(0.647)이 상위에 왔다. 청운대 같은 사업의 재공고는 "재공고 의심"(0.998)으로 표시했다. 테스트 16개 파일, 웹 빌드 통과.
- **남은 일:** 최근 순 80건만 모아 실제 공고일 범위가 약 6주(2026-10-05~11-16)다(M24에서 수집기 수정). 상수도·GIS 사업이 없어 상수도관은 일반 AI 사업만 나왔다. 범위 확대(기간·키워드·건수)와 HWP 제안요청서 처리, 유사도 기준의 정답 평가가 후속 과제다.

## 변경 내용

- `src/bid_review/rag/past_projects.py` (신규)
  - `collect_past_projects()`: 7일 단위로 공고를 수집하고, ICT 서비스만 남긴다. 첨부 API에서 PDF 제안요청서를 찾아 `data/past_rfps/<공고번호>-<차수>/{rfp.pdf, meta.json}`에 저장한다. meta에는 원 URL·SHA-256·조회 시각을 남긴다.
  - `fetch_awards()`: 낙찰 API를 **7일 단위**로 조회한다(키워드 조회는 15·30일 구간에서 07 "입력범위값 초과"). 오류 응답은 "낙찰 없음"과 구분해 실패 구간으로 센다.
  - `project_profile()`: RFP 앞 12쪽에서 사업 개요·목적·범위 제목이 있는 쪽을 골라 연락처 행을 지우고(M1 개인정보 필터 재사용) 2,500자 프로필을 만든다.
  - `build_past_project_index()`: 공고번호별 최신 차수만 남기고, **공고명+수요기관이 같은 재공고는 한 사업으로 묶는다**(관련 공고번호 목록 보존, 낙찰은 어느 공고에서든). 프로필을 임베딩해 `outputs/rag/past_projects.{json,npy}`에 저장한다.
  - `search_similar_projects()`: 유사도 0.60 이상 상위 5건을 낸다. 현재 공고번호와 관련된 사업은 제외한다. 유사도 0.95 이상이거나 사업명이 같으면 `same_project_suspected`로 표시한다. 색인 파일이 서로 맞지 않으면 쓰지 않는다.
- `src/bid_review/rag/workflow.py`: `t2_company_match → t3_similar_projects → END`. T2가 실행됐을 때만 동작하고, 실패해도 흐름을 막지 않고 `similar_projects_status`에 사유를 남긴다. 질의 프로필에는 **나라장터 공식 공고명·수요기관을 우선** 쓴다(T1이 통합정보시스템 사업명을 "학사 및 일반행정시스템 서비스 영역 개선"으로 잘못 뽑은 사례). State에 `similar_projects`, `similar_projects_status`를 추가했다.
- `web/src/components/tabs/CoreReviewTab.tsx`: T2 결과 아래에 "과거 유사 사업 (Agent 3)" 패널을 추가했다. 유사도, 재공고 의심, 낙찰자·금액(공고번호 일치 시), 관련 공고번호, 나라장터 링크를 보여준다.
- `scripts/build_past_projects.py` (신규): 수집 + 색인. `--index-only`로 색인만 다시 만든다.
- `tests/test_semantic.py`: 임계값, 현재 공고 제외, 재공고 표시(유사도·사업명), 색인 불일치 거부, 낙찰 7일 분할과 오류 구간 집계를 검증한다.

## 구현 중 발견한 문제

1. **낙찰 0건으로 조용히 실패:** 30일 구간 조회가 07 오류였는데, 오류 응답을 빈 결과로 처리했다. 7일 구간으로 바꾸고 실패 구간을 세도록 했다(0 → 1,599건).
2. **같은 사업 중복:** 재공고 차수, 그리고 새 공고번호로 나온 재공고가 각각 결과에 나왔다. 공고번호, 그다음 공고명+수요기관으로 묶었다(공고 77건 → 사업 63건).
3. **T1 사업명 오류가 질의에 반영됨:** 공식 공고명을 우선 쓰도록 바꿨다. 이후 재공고가 0.919→0.998로 잡혔다.
4. 실행 중 OpenAI `APIConnectionError`가 두 번 났으나 `SemanticUnavailable`로 처리됐고, 재시도하자 정상이었다.

## 판단 원칙

- 유사도는 "비교해 볼 만한 과거 사업" 후보일 뿐이다. 같은 사업이나 유사 실적 인정, 낙찰 가능성을 판정하지 않는다.
- 낙찰 정보는 공고번호가 정확히 일치할 때만 보여준다. 사업명이 비슷하다는 이유로 연결하지 않는다(M9).

## 정정 (M25)

`project_profile()`이 RFP 목차("사업개요 ·····1")부터 잘라, M23의 유사도는 목차끼리 비교한 값이었다. M25에서 목차를 건너뛰도록 고치고 색인을 다시 만들었다. 위 라이브 결과표는 수정 전 값이다. 수정 후에도 통합정보시스템(대학 학사)·CDW(병원 임상데이터) 상위 경향은 같았다.
