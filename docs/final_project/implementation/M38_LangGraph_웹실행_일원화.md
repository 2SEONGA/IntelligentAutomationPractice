# M38 웹 첫 실행 LangGraph 일원화 (1단계: offline)

- 작업일: 2026-11-20
- 결정: 이성아(2026-11-20) — 절충안. 웹 offline 실행을 LangGraph로 바꾸고, live(CrewAI LLM 브리핑)는 다음 단계에서 T4 뒤로 옮긴다.
- 관련: `회의_개선점/261118/종합_QA_검토_및_개선점.md` 2장 2·7번, QA 피드백 #2

## 1. 왜 바꿨나

웹에서 공고를 올리면 CrewAI 경로(`run.py`)가 **검증 없이** T1 추출 → 회사 매칭 → 시장 → 보고서를 먼저 만들었다. LangGraph의 T1.5 검증은 담당자가 "핵심정보 검증" 탭에서 따로 눌러야 돌았고, 승인 뒤 다시 만든 T4 결과는 목록·결재 화면의 보고서와 따로 놀았다. "검증되지 않은 T1 값은 T2·T3·T4로 넘기지 않는다"는 설계와 실제 웹 동작이 반대였다.

## 2. 바뀐 흐름

```
[전] 업로드 → run.py(CrewAI): 보고서 완성(검증 없음)
               └ (나중에 버튼) LangGraph: T1 다시 → T1.5 → 승인 → T2·T3·T4 (보고서 또 하나)

[후] 업로드 → LangGraph: T1 → 나라장터 조회 → T1.5
               ├ confirmed ─────────────▶ T2 → T3 → 평가 → T4 보고서
               └ 확인 필요 → "검토 대기" 보류 보고서 (중단 지점 저장)
                              └ 담당자 승인 → 같은 실행 이어서 T2 → T3 → 평가 → T4 보고서(새 보고서)
```

| 항목 | 전 | 후 |
|---|---|---|
| 업로드 직후 | CrewAI 보고서(검증 없음) | T1.5 통과 시 T4 보고서, 아니면 "검토 대기" 보류 보고서 |
| T1.5 검증 | 버튼을 눌러야 실행 | 항상 먼저 실행 |
| 승인 | T1부터 다시 실행, 목록 보고서는 그대로 | 저장된 지점에서 이어 가고 T4 보고서가 현재 보고서가 됨 |
| T1 추출 | 2번 | 1번 |
| 체크리스트 K2·K3 자동 판정 | 검증을 따로 돌린 건만 | offline 웹 실행 전부(공고함에서 시작한 건) |
| 감사 기록 | 검증 버튼 이후만 | 첫 실행(`analyze`, system)부터 승인까지 한 이력 |

| 단계 | 결과 |

## 5. 한계와 다음 단계

> 2026-11-20 M39에서 live(시장조사 옵션 제외)와 직접 업로드 공고번호를 처리했다. `M39_일원화_보완_오탐_평가캐시.md` 참고.

- **live 모드는 아직 `run.py`(CrewAI).** 다음 단계: T4 뒤에 CrewAI 브리핑 Agent가 검증된 결과(compact 요약)만 받아 요약문을 쓰게 하고, live도 LangGraph로 시작한다. 나라장터 낙찰 실시간 조회(Agent 3 시장)는 T3 낙찰 연결과 합칠지 정해야 한다.
- **직접 업로드한 건은 공고번호가 없어** 나라장터 조회를 건너뛴다(공고문 PDF에서 공고번호를 읽긴 하지만 조회에 쓰지 않음). 업로드 화면에 공고번호 입력을 두거나, T1이 읽은 공고번호로 조회하게 바꿀 수 있다.
- 한 검토 건 폴더에 보고서가 여러 개 쌓인다(검토 대기 → T4). 목록·결재는 최신 보고서만 보므로 동작에는 문제없다.
- T2·T3 병렬 실측(M37)은 그래프를 직접 돌린 것이라 이번 변경과 무관하게 그대로 유효하다.
