# M17 나라장터 용역변경이력 연결

작성일: 2026-11-17  
상태: 완료 (라이브 검증).

## 요약

- **한 일:** 공고번호로 용역변경이력(정정 차수·변경항목·변경 전/후 값)을 조회해 T1.5 결과와 검토 화면에 연결했다. 변경이력이 있으면 T1.5를 사람 검토로 보낸다.
- **결과:** 상수도관 공고 R26BK01762350은 변경이력 0건(번호 조회 + 기간 스캔으로 교차 확인). 변경이 있는 공고(R26BK01734777)에서는 `changes_found`와 검토 사유가 생성됨을 확인. 테스트 15개 파일 통과, 웹 빌드 통과.
- **남은 일:** 변경 후 값을 claim별로 자동 대입하지는 않는다(담당자 대조). 다른 업무구분(물품·공사)은 범위 밖.

## 변경 내용

- `src/bid_review/web/notices.py`
  - `fetch_notice_change_history()`: `BidPublicInfoService02/getBidPblancListInfoChgHstryServc02`, `inqryDiv=2` + 공고번호. 모든 차수의 행을 시간순으로 반환하고 다른 공고 행은 제외한다. 보존 필드: `bidNtceOrd`, `chgDt`, `chgDataDivNm`, `chgItemNm`, `bfchgVal`, `afchgVal`.
  - `fetch_notice_by_number()`가 첨부정보와 함께 변경이력을 조회한다. 실패 시 `status=unavailable`과 오류를 기록하고 단건 조회 자체는 계속한다.
- `src/bid_review/rag/verification.py`
  - `CoreInfoVerification.g2b_change_history` 추가.
  - `change_history_reason()`: 변경 행이 있으면 "변경이력 N건(항목들)… 담당자가 대조" 사유를 만든다. 다른 범주가 모두 확인돼도 종합 상태를 `human_review`로 내려 T2 자동 진행을 막는다.
- `src/bid_review/rag/workflow.py`: 조회 결과를 T1.5에 전달.
- `web/src/components/tabs/CoreReviewTab.tsx`: 변경이력 상태와 각 변경 행(일시·차수·항목·전→후)을 표시.

## 판단 원칙

- 변경이 있다는 사실만으로 어느 값이 맞는지 자동 결정하지 않는다. 차수가 크다는 이유로 최신 판본이라고 단정하지 않는다(M14 원칙 유지).
- 조회 실패(`unavailable`)는 화면에 표시하되 그 자체로 상태를 바꾸지 않는다. 기존 API 조회 상태·첨부 비교가 이미 출처 접근 실패를 다룬다.
