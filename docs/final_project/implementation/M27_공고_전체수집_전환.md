# M27 공고 전체 수집 전환

작성일: 2026-11-17  
상태: 완료 (테스트·빌드 통과, 저장소 사본으로 30일 라이브 수집 확인). 실제 공고함 저장소는 아직 다시 수집하지 않음.

## 요약

- **한 일:** M26 결정에 따라 웹앱 공고 수집을 공고명 키워드 5개에서 **키워드 없는 전체 조회**로 바꿨다. 전체 수집이면 30일 약 1.4만 건이 ICT 분야가 아니므로, 이런 공고는 저장하지 않고 건수만 기록한다. 공고함·대시보드·판단 기준 화면의 키워드 표시도 "전체 수집"으로 바꿨다.
- **결과:** 30일 라이브 수집(저장소 사본)에서 17,453건을 76초에 받았고, 검토 대상 66 · 확인 필요 32로 M26 측정과 같았다. ICT 아님 14,208건은 저장하지 않았고, 저장소는 771 → 3,845건(1.8MB → 9.1MB)이 됐다. 백엔드 테스트 16개 파일, 프론트 테스트 26개, 웹 빌드 통과.
- **남은 일:** 실제 공고함에서 "지금 수집"을 한 번 누르면 새 방식으로 채워진다. 저장소는 수집마다 ICT 공고가 쌓이므로(한 달 약 3천 건, 약 7MB) 마감이 오래 지난 공고 정리는 나중에 필요할 수 있다. Agent 3 과거 RFP 수집은 M28에서 같은 방식으로 바꾼다.

## 설계 판단

- **금액·마감으로 제외된 ICT 공고는 계속 저장한다.** 공고함의 "제외" 탭에서 담당자가 사유를 남기고 포함시키는 기능(HITL-2)이 있어서다. 제외 사유가 "ICT 분야 아님"인 공고만 버린다.
- **분야 판정의 공고명 키워드 대체 규칙(`field_keywords`)은 그대로 둔다.** 조달분류가 빈 공고에만 쓰이며, 30일 측정에서 8건뿐이었다.
- **수집 요청은 지금처럼 끝날 때까지 기다린다.** 76초는 화면 버튼의 로딩 표시로 충분하다고 보고 백그라운드 작업으로 바꾸지 않았다. 더 길어지면(기간 확대 등) 그때 바꾼다.
- `body.keywords`로 키워드를 직접 넘기는 API 호출은 이전처럼 동작한다(테스트용·특정 검색용).
