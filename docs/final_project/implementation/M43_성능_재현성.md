# M43 성능·재현성 — PDF 중복 읽기 제거, 질의 임베딩 캐시

- 작업일: 2026-11-25
- 범위: `남은 업무 순서` 4번
- 결과 요약: 같은 5건 순차 실행 전체 시간 **65.0초 → 52.7초(−18.9%)**, 모든 회차의 T1 값·판정·T3 결과·보고서 검증 동일

## 1. 어디가 중복이었나 (실측으로 찾음)

CDW RFP 70쪽을 `cProfile`로 잰 T1 시간 구성:

| 구간 | 비중 | 판단 |
|---|---:|---|
| pdfminer 레이아웃 해석(글자 좌표 읽기) | 약 40% | pdfplumber가 한 번만 한다. 줄일 수 없음 |
| pypdf 텍스트 추출 | 약 28% | **뺄 수 없음.** 일부 쪽은 pypdf 텍스트가 더 길어 채택된다(시연 CDW 2쪽, 과거 RFP 1건 40쪽 중 28쪽). 빼면 T1 결과가 바뀐다 |
| 겹친 글자 거르기 | 약 6% | 결과를 바꾸지 않고 줄이기 어려움(겹침 판정이 연쇄로 묶임) |
| 표 추출 | 약 4% | 필요 |

실제 중복은 T1 바깥에 있었다:
1. **T3가 같은 RFP를 처음부터 다시 연다.** T3 질의 프로필(`past_projects._rfp_pages`)이 T1이 이미 읽은 PDF를 pdfplumber로 다시 열고 겹친 글자도 다시 거른다. 5건 합계 14.5초(사례당 1.6~5.4초).
2. **T1.5 재해석 노드(`t1_reanalyze`)가 전체 T1을 다시 돈다.** 추출은 결정적이라 같은 결과를 또 만든다.

## 2. 고친 것

| 변경 | 내용 | 결과가 같은 이유 |
|---|---|---|
| T1 → T3 쪽 텍스트 재사용 (`pdf_chars.remember_plain_texts`, `agent01_rfp`, `past_projects._rfp_pages`) | T1이 쪽을 열었을 때 T3와 **같은 함수**(겹친 글자 거른 뒤 `extract_text()`)로 텍스트를 하나 더 계산해 둔다. T3는 파일 내용 SHA-256이 같을 때만 그대로 쓴다. 실패했던 쪽만 예전처럼 직접 읽는다 | 같은 쪽 객체·같은 함수. 시연 3건+과거 RFP 2건에서 직접 읽은 것과 **문자열이 완전히 같음** 확인 |
| T1 쪽 추출 캐시 (`RFPExtractor._extract_pages`) | 같은 프로세스에서 같은 파일·같은 설정을 다시 분석하면 저장한 결과의 깊은 복사본을 준다. 키 = 파일 SHA-256 + 파일 이름 + 추출 설정(짧은 쪽 기준·OCR 설정) + OCR 엔진 유무 | 추출은 결정적. 파일·설정·이름이 바뀌면 다시 읽음(테스트) |
| 겹침 없는 쪽은 원래 쪽 사용 (`pdf_chars.dedupe_overprint`) | 걸러낸 게 없으면 걸러낸 사본 대신 원래 쪽으로 레이아웃·표를 계산 | 같은 글자 집합 |

## 3. 질의 임베딩 캐시 (`semantic.cached_embedder`)

- M37에서 OpenAI 임베딩 점수가 같은 입력에도 소수 넷째 자리에서 흔들려 임계값 경계 후보가 실행마다 바뀌었다.
- 이제 `openai_embedder()`가 기본으로 캐시를 쓴다. 저장소 `outputs/rag/embedding_cache.sqlite3`.
- **키 = SHA-256(캐시 버전 + 모델명 + 텍스트).** 텍스트가 한 글자(공백 포함)라도 다르거나 모델이 바뀌면 다른 키라 잘못된 벡터를 재사용하지 않는다. 벡터를 만드는 방식이 바뀌면 `EMBEDDING_CACHE_VERSION`을 올린다.
- 벡터는 받은 값 그대로(float64) 저장해 첫 호출과 이후 호출이 **비트 단위로 같다.** 캐시에 없는 텍스트만 API로 보낸다.
- 캐시 파일을 못 만들거나 못 써도 임베딩은 그대로 동작한다.
- 색인 재구축(`build_past_project_index`)도 같은 캐시를 지나므로, 바뀌지 않은 프로필은 다시 돈을 쓰지 않는다.

- 방법: 순차 모드, 사례마다 3회, **회차마다 새 프로세스**(웹 작업처럼; 프로세스 안 캐시가 다음 회차를 빠르게 만드는 효과 제외). 담당자 검토에서 멈추는 사례는 같은 고정 승인으로 T4까지 진행. 변경 전은 HEAD(`35a8ede`) 작업 트리에서 같은 입력·같은 `outputs/rag`로 실행. `scripts/measure_sequential_runs.py`.
