# M48 T3 임계값 확정(0.70 유지)과 LLM 재정렬 도입

- 작업일: 2026-11-25
- 범위: `남은 업무 순서` 3번 마무리 (할 일 3·4)
- 담당자 결정 (2026-11-25)
  1. 임계값은 **0.70 유지** (M42 6장: 0.70~0.80을 0.01 간격으로 비교, 최고 0.71 F1 0.606이 0.70의 0.595와 거의 같음)
  2. **LLM 재정렬을 T3에 넣는다.**
  3. AI 대리 판정은 **팀원이 몇 건을 직접 확인**한다(아래 4장).
  4. A안 실험 코드(`live_awards.py`)는 그대로 둔다.

## 1. 왜 재정렬이 필요한가

임베딩 유사도는 "공공 SI 사업 일반"을 넓게 비슷하다고 본다. 상수도관 질의에 무관 후보(생성형 AI 인프라 0.798, 바다로시스템 0.781)가 0.73~0.80에 몰려 있어 **어떤 임계값으로도 걸러지지 않는다**(M42 6장). 그래서 점수 대신 "두 사업 내용이 정말 비슷한가"를 LLM에게 한 번 더 묻는다.

## 2. 동작 방식

```
T3: 과거 사업 110건과 유사도 계산 → 0.70 이상 상위 5건
    → (새로 추가) 후보마다 LLM에게 관련도 0·1·2 질문
    → 재정렬 점수 높은 순으로 다시 줄 세움 (같은 점수면 유사도 순)
```

| 점수 | 표시 | 처리 |
|---|---|---|
| 2 | 관련 | 위로 |
| 1 | 부분 | 중간 |
| 0 | **분야 다름** | **빼지 않고 맨 아래에 표시만** (AI가 틀릴 수 있으므로 사람이 최종 확인) |

- 같은 질문은 SQLite 캐시(`outputs/rag/rerank_cache.sqlite3`)에 저장해 다음 실행에서 같은 답을 쓴다. 재현성이 좋아지고 비용이 들지 않는다.
- 키가 없거나 호출이 실패하면 후보를 유사도 순서 그대로 두고 상태(`t3_rerank_status`)에 `partial …`을 남긴다. 첫 실패 뒤에는 더 호출하지 않는다. 흐름은 멈추지 않는다.
- 끄기: `config/settings.yaml`의 `past_projects.rerank: false`.

## 4. 시연 3건 T3 재확인 (실제 OpenAI 호출, gpt-4o-mini)

| 시연 | 후보(유사도 · 재정렬) | 분야 다름 | 추가 시간(첫 실행) |
|---|---|---:|---:|
| 통합정보시스템 | 같은 사업 재공고 1.000 관련 · 안동과학대 0.762 관련 · 바이오 LMS 0.721 부분 · AI 수요처 매칭 0.731 **분야 다름** · 수용가정보 유지관리 0.730 **분야 다름** | 2 | 11.6초 |
| 상수도관 | 지역혁신 데이터 플랫폼 0.746 부분 · 생성형 AI 인프라 0.798 ×2 · 바다로시스템 0.781 · 신용평가모형 0.733 **모두 분야 다름** | 4 | 6.5초 |
| CDW | 다기관 임상데이터 0.921 관련 · 거점병원 통합CDW 0.766 관련 · 차세대 정보시스템 0.754 부분 · 데이터 플랫폼 0.725 부분 · 지역혁신 데이터 플랫폼 0.723 부분 | 0 | 7.9초 |

- 상수도관: 재정렬 전에는 상위 5건이 모두 무관인데 그대로 나왔다. 이제 4건이 "분야 다름"으로 표시되고 맨 아래로 내려간다(완료 기준 "상수도관 무관 후보 제거"를 **표시 방식**으로 충족).
- AI 대리 판정과 다른 점: "AI 기반 지역혁신 데이터 플랫폼"(상수도관·CDW), "데이터 플랫폼 구축 사업"(CDW)은 판정표에서 무관인데 재정렬은 부분으로 봤다. 같은 모델·temperature 0이어도 M42 실험 때와 답이 조금 다를 수 있다. 이제는 캐시로 고정된다.
- 첫 실행은 T3가 7~12초 늘어난다(후보 5건 × 호출 1회). 같은 사례를 다시 실행하면 캐시로 거의 0초.
- 비용: 실행당 약 0.2센트(입력 약 2,500토큰 × 5회).
