# M4 의미 검색 (OpenAI 임베딩)

작성일: 2026-11-17  
상태: 완료. RFP·공고문 코퍼스 의미 검색과 T1.5 보조 검색 연결. Agent 2(회사 자료)·Agent 3(과거 RFP) 의미 검색은 후속.

## 요약

- **한 일:** 사용자 결정(2026-11-17, API 방식)에 따라 OpenAI `text-embedding-3-small`로 RAG 코퍼스 1,024 chunk를 임베딩했다. 의미 검색 CLI를 만들고, T1.5 추가 검색에서 키워드가 아무것도 못 찾은 질의에만 의미 검색을 보조로 붙였다.
- **결과:** 원문과 다른 표현의 질의("부가세 포함한 전체 예산 금액", "제안 서류를 언제까지 내야 하나")는 키워드 검색 결과가 0건이었지만 의미 검색은 관련 쪽을 찾았다. 세 공고 실행에서 보조 검색이 실제로 사용됐다. 의미 검색으로 붙은 근거는 모두 담당자 검토로 남고 자동 확정하지 않는다. 테스트 16개 파일, 웹 빌드 통과.
- **남은 일:** 회사 자료 RAG(M21)와 과거 RFP(Agent 3, M23)에 적용했다. 임계값은 정답 평가로 재조정 필요. 임계값 0.40은 표본 기준이라 정답 라벨 평가셋으로 다시 맞춰야 한다. LlamaIndex는 쓰지 않았다(아래 결정).

## 결정

| 선택 | 내용 | 이유 |
|---|---|---|
| 임베딩 | OpenAI API, `text-embedding-3-small` (1536차원) | 사용자 선택. 색인 대상이 공개 공고·RFP라 외부 전송 부담이 작고, 전체 색인 비용이 1센트 미만으로 추정됨 |
| 저장 | `outputs/rag/embeddings.npy` + `embeddings_meta.json` | chunk 텍스트·메타데이터는 기존 `chunks.jsonl`을 그대로 써서, 키워드 검색과 인용 형식이 같다 |
| 검색 | numpy 코사인 유사도 전수 비교 | 약 1천 chunk 규모에서 충분하다. 10만 단위로 커지면 벡터 저장소로 바꾼다 |
| LlamaIndex | 사용하지 않음 | 설치돼 있지 않고, 지금 필요한 기능(임베딩·유사도·필터)은 SDK와 numpy로 충분하다. 과제에서 LlamaIndex 사용이 필수라면 같은 벡터를 LlamaIndex 인덱스로 감싸면 된다 |
| 하이브리드(RRF) | 구현해 비교한 뒤 제거 | 키워드 "any" 검색의 잡음 결과가 순위를 끌어내려 의미 검색 단독보다 나빴다 |

## 변경 내용

- `src/bid_review/rag/semantic.py` (신규)
  - `build_semantic_index()`: chunk의 절 제목과 본문을 100개씩 임베딩하고, 정규화한 벡터와 코퍼스 SHA-256을 저장한다.
  - `search_semantic(query, document_id=, notice_no=, document_type=)`: 코사인 유사도 검색. 결과 메타데이터에 `semantic_score`를 붙이고, `rank = 1 - 유사도`로 둔다(키워드 bm25와 같이 낮을수록 좋음).
  - `SemanticUnavailable`: 색인이 없거나, 코퍼스가 바뀌어 색인이 오래됐거나(SHA 불일치), API 호출이 실패하면 이 예외를 낸다. 오류 메시지에는 예외 종류만 남기고 키·응답 본문은 넣지 않는다.
- `src/bid_review/rag/workflow.py`: `retrieve_targeted_evidence`에서 키워드(RFP + 공고문)가 0건인 질의에만 의미 검색을 실행한다. 범위는 같은 RFP 문서와 같은 공고의 공고문이고, 유사도 0.40 이상만 쓴다. 상태는 `semantic_retrieval_status`(used / not_needed / unavailable: 사유)로 State에 기록한다. 인용 check에는 "의미 검색(유사도 0.xx)으로 찾은 후보"라고 표시한다.
- `scripts/build_semantic_index.py` (신규), `scripts/search_rag.py --mode semantic`
- `tests/test_semantic.py` (신규): 가짜 임베딩으로 순위·필터·오래된 색인 거부·색인 없음·API 실패 시 키 미노출을 검증한다.
- `pyproject.toml`: `openai`, `numpy`를 직접 의존성으로 명시했다(기존에는 crewai를 통해 간접 설치).

## 실험 기록

1. **문서 제목을 임베딩 텍스트에 넣은 경우:** 같은 문서의 chunk끼리 벡터가 비슷해졌다. "영상 인공지능으로 수도관 상태 판별" 질의에서 "공고기관: 주식회사 셈즈" 메타데이터 행이 1위로 나왔다.
2. **절 제목 + 본문만 넣은 경우:** 유사도가 0.37→0.48로 올랐고, RFP 3쪽 사업금액, 공고문 3쪽 제안서 제출, SFR-003 요구사항처럼 관련 근거가 상위에 왔다. 이 방식을 채택했다.
3. **T1.5 보조 검색 표본 (세 공고, 후보 13건):** 무관한 표 행(CDW 66쪽 "위규 수준", 0.38) 2건을 보고 임계값을 0.35→0.40으로 올렸다. 남은 11건 중 관련 8건, 부분 관련 1건, 약한 관련 2건(목차 제목·서식 목록)이었다. 모두 담당자 검토 상태다.
