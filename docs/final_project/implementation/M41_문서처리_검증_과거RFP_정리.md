## 1. 문서 처리 재검증 (남은 업무 1번)

### 1-1. M40에서 통과하지 못한 테스트의 원인

M40 때 30개 파일 중 10개가 실패했다. 모두 코드 결함이 아니라 **이 Windows PC의 실행 환경**과 관련이 있었고, 그중 하나는 실제 운영 결함이었다.

| 테스트 | 원인 | 조치 |
|---|---|---|
| `test_app*` 4개 | `fastapi` 미설치. **`requirements-windows-py312.txt`에 `fastapi`가 아예 빠져 있음**(pyproject에는 `fastapi==0.143.0`) | 패키지 목록에 추가, 설치 |
| `test_hitl`, `test_state_history` | **`hitl_runtime.py`가 `fcntl`(macOS·Linux 전용)만 사용** → Windows에서 HITL 시작·승인·재개가 모두 import 단계에서 실패 | 운영체제별 파일 잠금(`fcntl` / Windows `msvcrt`)으로 수정 |
| `test_hitl` 재시작 검사 | 자식 프로세스 출력을 Windows 기본 인코딩(cp949)으로 읽다 한글 UTF-8에서 깨짐 | 테스트에서 UTF-8 지정 |
| `test_semantic` | 테스트가 한글 JSON을 인코딩 지정 없이 써서 cp949로 저장됨 | 테스트에서 UTF-8 지정. 같은 실수가 있던 `scripts/collect_g2b_awards.py`도 수정. 운영 코드(`src/`)는 AST로 전수 검사해 문제 없음 |
| `test_runs`, `test_checklist`, `test_workflow` | `outputs/offline/002_*`(CDW 오프라인 실행 결과)가 없음. `outputs/`는 Git에 없다 | `python run.py --mode offline --output outputs/offline --save-intermediate`로 생성(외부 API 호출 없음) |
| `test_runs` (생성 후) | CLI·웹 보고서 시각이 같을 때 정렬 순서가 OS의 파일 나열 순서에 따라 달라짐(macOS 통과, Windows 실패) | 순서에 의존하지 않게 테스트 수정 |
| `test_app_v2` | 웹 화면 빌드(`web/dist`)가 필요한데 이 PC에 Node.js가 없음 | **미해결(환경)**. `cd web && npm install && npm run build` 후 다시 확인 |

설치 중 주의: `fastapi 0.143.0`을 설치하면 `opentelemetry-api`가 1.45.2로 올라가 CrewAI가 쓰는 `opentelemetry-sdk 1.42.1`과 맞지 않아 `crew.py` import가 실패했다. `opentelemetry-api==1.42.1`로 되돌렸다(pip는 fastapi 요구 ≥1.44 경고를 내지만 import·웹 테스트는 통과). 새 가상환경을 만들 때도 같은 충돌이 생길 수 있다.

## 2. 과거 RFP 품질 정리 (남은 업무 2번)

### 2-1. 잘못 저장된 첨부 교체

전체 수집(`build_past_projects.py`)을 다시 돌리면 180일 공고를 새로 훑어 최대 48건이 새로 들어오고 `awards.json`(낙찰)도 다시 받아 "낙찰 연결 22건 유지"를 흔든다. 그래서 **한 건만 다시 받는 스크립트** `scripts/recollect_past_project.py`를 만들었다.
- 기존 폴더를 `outputs/backups/past_rfps/<공고>_<시각>/`에 먼저 복사(원본 보존).
- 수집기와 같은 규칙으로 고르고, 파일 형식(magic)·`hwp_text` 읽기 확인 후에만 교체. 실패하면 기존 폴더 그대로.
- 다른 공고와 `awards.json`은 건드리지 않음. 공고당 첨부정보 API 1회 + 다운로드 1회.
