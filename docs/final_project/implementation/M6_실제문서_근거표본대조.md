# M6 구현 기록 — 실제 RFP 금액·일정 근거 표본 대조

상태: 3개 원본의 금액/일정 표본 대조 및 참가자격 절 조건별 추출 보완 완료. 담당자 원문 대조와 전체 정확도 평가는 미완료  
작성일: 2026-11-12

## 요약

- **한 일:** 금액·일정 citation을 실제 RFP와 표본 대조해 과잉 검색을 발견하고 필드별 전용 질의·all 매칭으로 보정했다. 참가자격 절 조건별 추출도 보완.
- **결과:** 3건 재실행 완료. 상수도관 금액은 RFP 107,000,000원(VAT 별도) vs 배정예산 117,700,000원으로 VAT 기준 확인 필요.
- **남은 일:** 담당자 원문 대조, 표/다단 문서 점검, 전체 정확도 평가.

## 목적과 범위

LangGraph 출력의 금액·일정 citations가 실제 의미가 있는지 원문 PDF와 함께 표본 확인했다. 이 작업은 정답 라벨 기반의 전체 정확도 평가가 아니다. 한 번의 과잉 검색 사례를 발견해 검색 범위를 고친 후 같은 세 PDF에 다시 적용했다.

## 발견 및 보정

초기 검색은 금액 후보 누락 시 모든 금액 키워드를 OR로, 일정 후보 누락 시 모든 일정 키워드를 OR로 검색했다. 그 결과 추정가격 누락에 과업 수행실적표나 사업비 산출 서식 페이지가 근거 후보로 붙었다. 화면에 관련 없는 근거가 보여질 수 있어 아래처럼 변경했다.

- 금액 필드별 전용 질의: 예산/사업금액은 해당 용어, 추정가격은 추정가격/기초금액/예정가격으로 구분
- 일정 필드별 전용 질의: 제안서 제출 마감, 입찰 마감, 공동수급협정서 마감, 수행기간별로 분리
- 추가 검색은 질의의 모든 색인 단어가 함께 일치하는 all 검색으로 좁힘
- 하나의 chunk가 여러 검색어에 응답한 경우 연결된 검색어 목록을 보존해 검토 대상으로 연결

## 결론

검색 질의를 필드별로 한정하자 추정가격 미확인 항목에 잘못 붙던 무관한 표/서식 페이지가 사라졌다. 반대로 RFP가 “입찰공고문 참조”라고 안내하는 페이지는 실제로 찾아 사람 검토 근거로 제시됐다. 원문에서 제출기한 값을 찾을 수 없다는 사실과 값을 잘못 추출했다는 사실을 구분할 수 있게 됐다.

## 남은 검토

- 참가자격 범위 분류를 반영해 재실행한 뒤 원문과 대조했다. 핵심 누락을 확인했으므로 참가자격 검증은 완료로 볼 수 없다.
- 사업금액 범위와 VAT 기준은 실제 나라장터 첨부 RFP 판본 및 계약예산의 세부 산정 기준과 비교하지 않았다.
- 공동수급 마감/제안 시작 시각이 해당 RFP에 적용되지 않는 경우를 not_applicable로 확정하는 판정은 없다.
- 3건 표본만으로 정확도나 업무 적용 성능을 주장하지 않는다.

## 다음 순서

2. 제목이 다르거나 표/다단 레이아웃을 가진 문서에서 섹션 추출 누락/오탐을 점검한다.
3. 담당자가 검토 사유를 기록하고 승인/반려한 뒤, 승인된 한 건을 T2로 재개한다.
4. 적용성 검토 후 의미 검색 공급자와 LlamaIndex 연결을 확정한다.

## 참가자격 후보의 범위 분리 보완 (2026-11-12)

### 변경 내용

T1의 `eligibility_requirements`에 참가 가능 여부를 정하는 조건 외에 제안서 평가 배점, 제출 서식, 제출 절차, 계약 이후 보안 의무 및 계약금액 기준 사후 제재가 함께 섞이는 사례를 확인했다. T1.5 참가자격 검증에 보수적인 범위 분류를 추가했다.

- 입찰자격 판단 조건은 이전처럼 주체·조건·효과·예외·부정조건·증빙을 확인한다.
- 평가/배점, 서식/양식, 제출 절차 및 계약 후 의무/제재 후보는 자격 claim으로 검증하지 않고 `scope_exclusions`로 분리한다.
- 화면에서 분리된 문구와 페이지, 분류 사유를 접어 볼 수 있게 표시한다.
- 참가자격 고신호 키워드가 있는 미분류 페이지는 coverage 미완료로 남겨 자동 통과하지 않는다.

## 참가자격 후보와 원문 대조 (2026-11-12)

PDF 물리 페이지 번호를 기준으로 참가자격 절을 직접 확인했다. 아래는 세 문서 표본 대조 결과이며 전체 정확도 평가는 아니다.

### 상수도관 노후도 분석

- PDF 4쪽 `2.2 입찰 참가 자격`에는 가~바 6개 조건이 있다.
- T1은 가(법정 자격), 나(부정당업자 제한 해당 여부), 다(나라장터 등록) 3개를 자격 후보로 추출했다.
- 라(소프트웨어사업자 등록), 마(중소기업 확인), 바(대기업 참여 제한)는 같은 자격 절에 있으나 구조화 후보에서 빠졌다. 원문 인용과 적용 범위를 추가 검증해야 한다.
- PDF 4쪽 `2.3 공동도급`은 공동도급 불허를 별도로 설명한다. 입찰 참여 방식에 영향을 주므로 자격/입찰방식 중 어느 범주에서 검증할지 정해야 한다.
- 검색상 미분류 PDF 2쪽은 목차다. 27~39쪽 실적 평가·서식 안내는 본문 참가자격과 구별해야 한다. 현재 키워드 coverage 결과만으로는 이를 정밀하게 가르지 못한다.

### 임상연구정보검색시스템(CDW)

- PDF 38쪽(문서 인쇄면 35쪽) `Ⅴ. 제안안내 / 1 입찰자격`은 T1 후보 1개에 여러 조건을 긴 복합 문장으로 묶었다. 법정 입찰자격, 나라장터·SW사업자 등록, 대기업/중견기업 제한, 중소기업 확인, 유사 CDW 실적 조건이 있어 조건 단위 검증은 부족하다.
- 평가·협상 설명(PDF 40쪽), 제안서 효력(PDF 51쪽), 실적증명 서식(PDF 58쪽), 참여인력 서식(PDF 59쪽)은 입찰자격 자체와 구분해야 한다.
- PDF 61쪽 서약서의 “참가자격 박탈”은 허위 제출 시 제재 문맥이다. 이를 입찰 전 자격 요건으로 세지 않는 현재 범위 분류가 타당하다.
- 검색상 미분류 PDF 61쪽은 서약서 문구로 설명되지만, 실제 자격 절 PDF 38쪽을 검증 coverage가 확인했다는 뜻은 아니다.

### 통합정보시스템 고도화

- PDF 33쪽(문서 인쇄면 31쪽) `2 입찰 참가 자격`에는 법정 자격, SW사업자 신고, 대기업 참여 제한 준수, 직접생산증명, 최근 3년·15억 원 이상 실적, 정리절차/회생 신청 상태, 부정당업자 제한이 나열되어 있다.
- 이 자격 절은 T1 `eligibility_requirements`에 들어오지 않았다. 대신 PDF 22쪽 계약 이후 보안 위반 제재, PDF 34쪽 등록·제출 서류표, PDF 36쪽 협상적격자 상태, PDF 46쪽 평가 배점 및 서식 문구가 후보에 들어왔다.
- PDF 36쪽 부도·파산·해산·영업정지는 협상적격자 선정 시점에 관한 실격 조건이어서 사람 확인 대상으로 남기는 편이 적절하다. PDF 22쪽 정보누출 제재는 계약 후 의무이므로 입찰 전 자격과 분리한다.
- 검색상 미분류 PDF 2쪽은 목차였고 실제 자격 절 PDF 33쪽이 빠졌다. 현 coverage 검색만으로 자격 절 누락을 감지하지 못할 수 있다.

### 감사 결론과 후속 구현

현재 참가자격 검증의 중요한 한계는 (1) 문서별 자격 절을 완전하게 탐지하지 못함, (2) 복수 자격 요건이 단일 후보로 묶임, (3) 키워드 페이지 coverage가 목차·평가·서식과 본문 자격 조항을 구분하지 못함이다. 모든 문서가 사람 검토 상태라는 점만으로 누락이 해결되지는 않는다.

다음 구현 단위는 참가자격 전용 section retrieval/extraction이다. 자격 절의 경계와 페이지 근거를 찾고 조건별로 구조화한 뒤, 원문 조건 목록과 추출 결과의 누락·중복·복합 후보를 사람 검토로 보낸다. 일반 키워드 검색만으로 `coverage_complete=True`가 되지 않도록 유지한다. 구현 후 세 원문을 다시 대조하고 담당자 승인/T2 시연을 진행한다.


## 참가자격 절 추출 보완 및 재실행 (2026-11-12)

### 구현

- `src/bid_review/agent01_rfp.py`에서 목차/부록을 건너뛰고 제목이 명시된 입찰참가자격 절을 찾아 다음 번호 절 전까지 본문을 수집한다.
- `가./나./다.`, `○`, `-`, `l` 등 글머리표와 줄바꿈된 문장을 조건별 후보로 분리하고 PDF 페이지 근거와 `입찰참가자격 절` 출처를 기록한다.
- 번호 절에서 분리되어 인접 절에 놓이는 “공동도급은 허용하지 않음”도 별도의 입찰 참여 제한 후보로 보존한다.
- 절에서 추출한 조건을 기존 페이지 단위 후보보다 앞에 배치해 T1.5의 조건 ID가 원문 순서를 따르게 했다. 절 외부의 협상적격 조건(예: 부도/파산 상태)은 별도 후보로 남긴다.
- `src/bid_review/rag/verification.py`는 평가 배점, 제출 양식 및 계약 후 보안 제재를 참가자격 claim에서 분리한다. 띄어쓰기/줄바꿈이 달라진 PDF 문구도 비교할 수 있도록 분류 시 공백을 정규화했다.
- coverage는 명시적 자격 절을 실제 추출했는지와 자격 관련 미분류 문구를 기준으로 산출하도록 바꿨다. 목차/평가/서식의 단순 키워드 검색 결과는 미완료 판정에 직접 합산하지 않는다. 화면의 coverage 설명에는 이것이 구조 추출 상태이며 자격 충족 판정이 아니라는 점을 명시한다.

갱신된 LangGraph 결과는 `outputs/langgraph_reviews/*.json`에 있다. 모든 실행은 `human_review_required`로 끝났다. 자동 절 추출/coverage 완료 표시는 요건 충족이나 법적 적합 판단을 뜻하지 않는다. 특히 상수도 사업의 대기업 참여 제한 문구, 중소기업 자격 증빙, 부정당업자 해당 여부, 공동도급 불허 및 각 공고의 복합/예외 조건은 담당자가 원문과 조건별로 확인해야 한다.

### 확인 및 한계

- PDF 원문 절 후보 확인: 세 문서 모두 명시적 자격 절을 찾아 조건별 후보와 페이지 근거 생성
- Python `compileall`: 통과
- 웹 프로덕션 빌드: `npm run build` 통과 (이번 변경에서 API/UI 계약은 변경하지 않음)
- 테스트 스위트, 사람의 실제 승인, T2 재개는 실행하지 않음
- 현재 제목/목록 기반 추출은 표·다단 레이아웃이나 번호가 없는 자격 절에서 조건 누락/병합이 생길 수 있다. 문서마다 다른 절 제목과 예외 구조를 전체 데이터로 검증하지 않았다. coverage 완료를 자동 업무 승인으로 사용해서는 안 된다.

### 다음 순서

1. 사람 검토 화면에서 세 문서의 조건·인용 페이지·범위 밖 문구를 열어 담당자가 원문 대조한다.
2. 특히 표/다단 레이아웃과 제목이 다른 PDF를 추가해 섹션 탐지의 누락 및 오탐을 확인하고, 필요하면 표 구조 추출을 보완한다.
3. 승인/반려 사유를 담당자가 입력한 뒤 한 건을 T2로 재개해 감사 이력을 확인한다.
4. 이후 의미 검색 공급자 선택과 LlamaIndex 연결을 진행한다.
