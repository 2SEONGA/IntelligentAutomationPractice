# M44 live 시장조사 통합 — A안(실시간 낙찰 조회 Node)·B안(T3 색인 낙찰만) 구현과 비교

- 작업일: 2026-11-25
- 범위: `남은 업무 순서` 5번. **어느 안을 운영에 쓸지는 담당자 결정 대기.** 운영 기본값·`run.py` 경로는 바꾸지 않았다.

## 1. 지금 구조(바꾸기 전)

| 실행 | 경로 | 시장·낙찰 정보 |
|---|---|---|
| 웹 offline / live(시장조사 끔) | LangGraph (T1 → T1.5 → 승인 → T2 → T3 → T2·T3 평가 → T4) | T4가 T3 후보에 붙은 **색인 낙찰정보**(`data/past_rfps/awards.json`, 수집 시점 값)로 시장 절을 만든다 (`report_adapter.build_market_result`) |
| 웹 live + "나라장터 시장조사" 켬 | `run.py`(CrewAI 시장 Agent) | `G2BAwardClient`가 낙찰정보서비스를 사업명·수요기관으로 실시간 검색 |

즉 **B안은 이미 LangGraph 경로의 동작**이고, A안은 LangGraph 안에 실시간 조회를 넣는 것이다.

## 2. 구현

### A안 — `t3_live_awards` Node (실험, 기본 꺼짐)
- `src/bid_review/rag/live_awards.py`(신규) + `create_bid_review_graph(market_mode="live_awards")`일 때만 그래프에 Node 추가: `t3_similar_projects → t3_live_awards → t23_evaluate`(순차·병렬 모두).
- 후보마다 **후보 자신의 공고번호**로 낙찰정보서비스(`getScsbidListSttusServc`, `inqryDiv=4`)를 다시 조회한다.
- 연결 규칙: 공고번호가 정확히 같고, 공고명이 후보 사업명과 같을 때만 붙인다(공백·기호 무시). 재공고 묶음의 다른 번호 낙찰은 붙이지 않는다 — 기존 T2·T3 검증(`agent23_evaluation`의 공고번호·URL 일치 검사)과 같은 기준이라 검증을 우회하지 않는다.
- 후보별 상태: `new_award`(색인에 없던 낙찰), `same_as_index`, `updated`(낙찰자·금액이 바뀜, 전후 값 기록), `name_mismatch`(번호는 같고 공고명이 다름 → 붙이지 않음), `no_award_yet`, `unavailable`.
- 실패 처리: API 실패·키 미등록이면 **첫 실패에서 멈추고 더 부르지 않으며 색인 낙찰정보를 그대로 둔다.** 보고서는 계속 만들어진다. 서비스 키는 결과·오류에 남기지 않는다.
- 호출 상한: 후보 10건(=호출 10회).
- 위치가 T3 뒤라서 T1.5 검증·담당자 승인(HITL)을 지난 뒤에만 실행된다. CrewAI 브리핑은 T4 결과만 받으므로 충돌하지 않는다.

### B안 — 색인 낙찰만 (기본값, 코드 변경 없음)
- `market_mode="index"`(기본). 그래프는 이전과 완전히 같다(테스트로 확인).
- B안을 운영에 채택하면 할 일: `jobs.build_command`의 `market_api` 분기와 웹의 "나라장터 시장조사" 체크박스 제거. **이번에는 하지 않았다(결정 전).**

## 3. 같은 조건 비교 (실제 API)

같은 후보 10건(색인에서 공고번호 순, 낙찰 연결 5건 + 없음 5건)에 두 안을 적용했다(`scripts/compare_market_modes.py`).

| 항목 | B안 (색인만) | A안 (실시간 재조회) |
|---|---|---|
| 실행시간 | 0초 | 0.27초 (호출 1회 후 중단) |
| API 호출 | 0회 | 1회 (첫 실패에서 멈춤) |
| 낙찰 연결 | 5건 | 5건 (색인 값 유지) |
| 결과 | — | **전 후보 `unavailable`: 낙찰정보 API 오류 30 "등록되지 않은 서비스키"** |
| 데이터 최신성 | `awards.json` 수집 기간 2026-05-21 ~ 2026-11-17 | 조회 시각(키가 등록되면 실행 시점 값) |

**중요한 발견:** 지금 `.env`의 두 나라장터 키는 **입찰공고정보서비스에는 등록돼 있지만 낙찰정보서비스(ScsbidInfoService)에는 등록돼 있지 않다.** 그래서
- A안의 실제 낙찰 조회는 지금 검증할 수 없다(모의 테스트만 통과).
- **기존 `run.py` 시장조사 경로도 같은 이유로 실패한다**(`G2BAwardClient` 실측: HTTP 403). 즉 웹에서 "나라장터 시장조사"를 켜도 지금은 낙찰 조회가 되지 않는다.
- 공공데이터포털에서 [조달청_나라장터 낙찰정보서비스](https://www.data.go.kr/data/15129397/openapi.do) 활용신청 후 다시 실행하면 A안 실측이 가능하다(`python scripts/compare_market_modes.py`).

## 4. 비교 정리(구현·설계 기준)

| 항목 | A안 | B안 |
|---|---|---|
| 검색·낙찰 결과 | 색인 이후 새로 난 낙찰(`new_award`)·바뀐 값(`updated`)을 반영 | 색인 수집 시점 값만 |
| 데이터 최신성 | 실행 시점 | 색인 재수집 주기(지금 2026-11-17까지) |
| 출처·근거 정확성 | 공고번호 정확 일치 + 공고명 확인, 실시간 조회 시각 기록 | 공고번호 정확 일치(색인 만들 때), 출처 URL |
| 실행시간 | 후보당 API 1회(10건이면 수 초, 네트워크에 따라 다름) | 추가 시간 없음 |
| API 호출·비용 | 실행마다 최대 10회(무료, 하루 한도 소모) | 0회 |
| 오류 시 안정성 | 실패해도 색인 값으로 계속(검증됨: 1회 실패 → 중단 → 값 유지) | 외부 의존 없음 |
| 구현·유지보수 | 모듈 1개·Node 1개 추가, 낙찰 API 키 활용신청 필요 | 추가 없음. 운영 채택 시 `run.py` 시장조사 경로·체크박스 정리 |
| LangGraph·CrewAI 호환 | T3 뒤 Node, HITL 뒤에만 실행, 기존 검증 규칙 그대로 | 현재 구조 그대로 |
| 기존 시장조사 제거 시 정보 손실 | — | CrewAI 시장 Agent의 사업명·수요기관 키워드 검색(유사 과거사업 탐색)이 없어진다. 단, T3 유사 사업 검색이 같은 목적을 원문 프로필로 더 정확하게 하고, 그 경로는 지금 키로 어차피 실패한다 |

## 5. 검증

- `tests/test_market_modes.py`(신규, 모의): 공고번호·공고명 일치 시에만 연결, 상태 5종, 입력 불변, 실패 시 1회 후 중단·색인 값 유지·키 미노출, 호출 상한, 기본 그래프 불변(순차·병렬), 잘못된 모드 거부.
- 실제: 위 3장(키 미등록 실패 경로).

## 6. 결정이 필요한 것

- A안을 쓰려면: 낙찰정보서비스 활용신청 → `compare_market_modes.py` 실측 → 웹 옵션을 `market_mode="live_awards"`로 연결.
- B안을 쓰려면: `run.py` 시장조사 분기·웹 체크박스 제거, 화면 문구 수정.
