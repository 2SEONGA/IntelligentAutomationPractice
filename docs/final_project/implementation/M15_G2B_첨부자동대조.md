## 요약

- **한 일:** 공식 첨부파일정보 API 직접 조회와 저장 PDF/API 첨부 SHA-256 비교를 T1.5에 연결하고, Service02 엔드포인트 `02` 접미사 오류를 고쳤다.
- **결과:** 라이브 검증: 첨부 2건 조회, 공고문 byte_match, RFP 원본과 API 첨부 바이트 동일. 테스트 15개 파일 통과.
- **남은 일:** 금액 교차출처·제안서 기한 담당자 판정, T2 승인.

## 목표

공고 목록 응답에 섞여 오는 첨부 필드 대신, 공식 **첨부파일정보조회** 오퍼레이션을 공고번호·차수로 직접 호출해 첨부 문서 구분·파일명·URL을 확보한다. 실행 폴더에 저장된 `notice.pdf`와 현재 API 첨부의 원본 바이트 SHA-256을 비교해 T1.5 기록과 검토 화면에 남긴다.

## 변경 내용

- `src/bid_review/web/notices.py`
  - `fetch_notice_attachment_info()`: `BidPublicInfoService02/getBidPblancListInfoAtchFileInfo02`를 `inqryDiv=2`, `bsnsDivCd=5`(용역), 공고번호·차수로 조회한다. 다른 차수 행은 제외한다.
  - `compare_notice_pdf_bytes()`: 공고서 첨부를 내려받아 SHA-256을 비교한다. 결과 상태는 `byte_match`, `byte_mismatch`, `local_pdf_missing`, `g2b_notice_attachment_missing`, `invalid_attachment_url`, `download_unavailable`, `download_too_large`, `download_not_pdf` 중 하나다.
  - `fetch_notice_by_number()`: 첨부정보 조회가 실패하면 목록 응답 첨부로 fallback하고 `metadata_source`에 출처를 표시한다.
  - **엔드포인트 수정(라이브 검증 중 발견):** Service02 오퍼레이션은 이름 끝에 `02`가 붙어야 한다. 접미사 없는 이름은 `12 해당 오픈API 서비스가 없거나 폐기됨`을 반환해 M13 단건 조회와 공고 수집(`collect`)이 라이브에서 동작하지 않고 있었다.
    - 공고 수집: `getBidPblancListInfoServcPPSSrch02` (키워드+기간 검색)
    - 공고번호 단건 조회: `getBidPblancListInfoServc02` (`PPSSrch02`는 `inqryDiv=2` 공고번호 조건을 무시하고 무관한 공고 1,073건을 반환함)
- `src/bid_review/rag/workflow.py`, `verification.py`: 첨부 조회 상태·오류·비교 결과를 `CoreInfoVerification`에 저장한다.
- `web/src/components/tabs/CoreReviewTab.tsx`: 첨부 메타데이터 조회 상태, 바이트 비교 결과, 로컬/API SHA-256을 표시한다. (빌드 오류였던 `verification?.` 누락 수정)
