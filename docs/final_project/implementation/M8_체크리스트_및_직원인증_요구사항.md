# M8 검토 기록 — 체크리스트 화면과 직원 인증 요구사항

작성일: 2026-11-12  
상태: 기존 웹 기능 확인 및 후속 인증 요구사항 기록 완료. 인증 기능 구현은 미착수.

## 요약

- **한 일:** Go/No-Go 체크리스트 탭의 역할·권한 흐름을 확인하고 직원별 인증 요구사항을 기록했다.
- **결과:** 체크리스트는 T1.5와 별도 탭·기록으로 유지. 현재 역할 선택(X-Role)은 보안 인증이 아님을 명시.
- **남은 일:** 사내 SSO/계정 정책 확정 후 구현(미착수).

## 사용자 의견

- 기존 Go/No-Go 체크리스트도 웹에서 검토할 수 있어야 한다.
- 추후 역할 선택창을 직원별 사내 ID/비밀번호 인증으로 바꾸고, 직원별 권한을 확인해야 한다.

## 확인한 체크리스트 화면

결과 화면 RunResult에 다음 탭이 별도로 있다.

1. 핵심정보 검증: 사업금액·참가자격·기간 등 T1.5 검증, RAG/PDF 인용, 범위 밖 분류, 담당자 검토 및 T2 재개.
2. Go/No-Go 체크리스트: 참가 가능 여부 탈락요건, 매력도·수주 가능성 점수, 근거 텍스트, PDF 페이지 링크 및 담당자 수정.

체크리스트는 핵심정보 검증을 대체하지 않는다. 서로 다른 업무 판단이므로 같은 결과 화면에서 별도 탭과 기록으로 제공하는 것이 현재 구조와 맞는다.

## 실제 저장 결과 확인

현재 웹 실행 목록에서 세 사업의 최신 웹 보고서를 읽기 전용으로 확인했다.

| 사업 | 실행 시각 (KST) | 체크리스트 항목 | 체크리스트 권고 |
|---|---|---:|---|
| 상수도관 노후도 분석 | 2026-10-27 22:32 | 9 | 보류 |
| 임상연구정보검색시스템(CDW) | 2026-10-27 22:31 | 9 | 보류 |
| 통합정보시스템 고도화 | 2026-10-27 22:23 | 9 | 보류 |

세 건 모두 상세 실행 자료가 있어 체크리스트 탭에서 판단 근거를 볼 수 있다. 자동값과 담당자 수정값은 UI에서 구분되고, 수정은 현재 보고서의 체크리스트 sidecar에 저장된다. 이번 확인 중 체크리스트 값을 변경하지 않았다.

## 현재 역할 선택과 인증 차이

현재 시작 화면은 staff/director 중 역할을 고르는 테스트용 UI다. 프론트엔드는 선택을 브라우저 sessionStorage에 보관하고 X-Role 헤더로 보낸다. 백엔드는 이 헤더 문자열을 허용 역할과 비교해 권한을 결정한다. 직원 신원, 비밀번호 또는 사내 계정은 검증하지 않는다. 따라서 실제 보안 로그인으로 사용하면 안 된다. 화면의 역할 안내 문구에도 테스트 선택이며 인증이 아니라고 표시되어 있다.

## 후속 인증 설계 요구사항

실제 사내 사용을 준비할 때 다음을 먼저 결정해야 한다.

- 사내 ID/비밀번호를 앱에서 직접 검증할지, 사내 SSO/디렉터리 제공자에 연결할지. 사내 인증 제공자가 있으면 앱에서 계정 비밀번호를 보관하지 않는 방식을 우선 검토한다.
- 직원 계정과 역할을 누가, 어떤 절차로 부여하고 회수할지.
- 서버가 검증한 로그인 세션만 권한 근거로 받아들이고, 클라이언트가 보낸 X-Role만으로 권한을 승인하지 않도록 변경.
- 감사 이력에 직원 식별자와 검증된 역할, 동작, 시각, 검토 사유를 기록.
- 로그아웃, 세션 만료, 직원 계정 비활성화 처리.
- 실제 사내 인증 시스템/담당자/테스트 계정이 정해진 뒤 통합 시연.

사용자가 제안한 직원별 로그인을 향후 요구사항으로 기록했으며, 현재 역할 선택을 보안 인증으로 취급하지 않는다. 조직의 인증 수단이 정해지기 전에는 로컬 ID/비밀번호 저장 기능을 임의로 만들지 않는다.

## 미완료 항목

- 담당자가 웹에서 Go/No-Go 각 항목의 근거와 PDF를 직접 검토하고 수정 여부를 결정.
- 인증 제공자와 역할 관리 정책을 조직 담당자와 협의.
- 인증 구현 이후 계정/역할 권한, 비활성 사용자, 세션 만료 및 감사 이력을 검증.
