02
Problem

핵심정보가 틀리면 입찰 판단까지 틀린다

업무 범위

시작나라장터 공고 + RFP·공고문 확보
주요 작업핵심정보 추출 → 근거 검증 → 회사 역량·유사 사업 분석 → 보고서
종료근거가 확인된 보고서, 또는 담당자 확인 요청
최종 Go/No-Go는 사업본부장

검증 대상 3개 범주

  • 사업금액
    예산/추정가격, VAT 포함·별도, 총액/연차
  • 참가자격
    주체·요건·제한·공동수급·예외
  • 기간·기한
    수행기간, 제안서/입찰 마감, 일정 종류
기존 시스템 (3~5주차)에서 확인한 오류
사업원문 금액개선 전
통합정보시스템3억 원10억 원 이상으로 오인
AI 영상 상수도관1억 700만 원금액 누락
의료 CDW10억 7,050만 원금액 누락
추출 오류가 그대로 다음 단계로 전파 → 규모 기준·권고가 왜곡
정답 문구를 프롬프트에 넣는 방식은 새 RFP에 사용 불가

Verify First

웹 실행을 "검증 먼저" 구조로 일원화

전

업로드 → CrewAI가 검증 없이 보고서

  • T1.5는 담당자가 버튼을 눌러야 실행
  • 승인 후 결과와 목록·결재 보고서가 따로 놂 (보고서 2개)
  • T1 추출 2번 · 웹 첫 검증은 나라장터 조회 생략(버그)
후 (M36–M39)

업로드 → LangGraph: T1 → 나라장터 → T1.5

  • 확인 필요면 "검토 대기" 보류 보고서, 승인하면 같은 실행 재개 → T4 보고서
  • 체크리스트 K2·K3를 T1.5 결과로 업로드 직후 자동 판정
  • 직접 업로드도 나라장터 공고번호 입력 → 교차검증
  • live: T4 검증 뒤 CrewAI 브리핑(판정은 규칙 기반 유지)
상수도관 실경로업로드승인T1 실행체크리스트
offline8.9초 · 담당자 검토에서 중단11.7초 · T4 보고서1회K2 미충족 · K3 충족 → No-Go 권고
live15.9초50.4초 · T4 + CrewAI 브리핑1회브리핑: "보류 — 사업금액 내부 기준 미달"

지킨 원칙

  • 유사도·브리핑은 판정이 아니라 단서
