## 1. 해결할 업무 문제

**사업금액·참가자격·기간을 잘못 읽으면 입찰 판단도 흔들립니다.**

공고/RFP 접수 → 정보 추출·근거 검증 → 역량·시장 분석 → 담당자·본부장 검토

시작: 나라장터 공고와 RFP 확보  
종료: 근거가 확인된 검토 결과 또는 담당자 확인 요청

## 2. 기존 프로젝트에서 확인한 문제

5주차 동일 RFP 3건 비교:

- 통합정보시스템: 원문 **3억 원** → 개선 전 **10억 원 이상**으로 오기재
- AI·GIS: 원문 **1억 700만 원** → 보고서에서 금액 누락
- 의료 CDW: 원문 **10억 7,050만 원** → 보고서에서 금액 누락

잘못된 정보가 규모 판정과 후속 권고에 이어질 수 있었습니다.

## 3. 제안: T1과 후속 분석 사이의 T1.5

`T1 정보 추출 → T1.5 원문 근거 검증 → T2 역량 매칭 + T3 시장 조사 → T4 보고서`

- 확인됨: 근거와 추출 정보 일치
- 추가 검색: 관련 원문 구간을 더 탐색
- 충돌·불확실: 근거와 질문을 담당자에게 전달

최종 Go/No-Go 결정은 사람이 합니다.

## 4. 실제 데이터와 활용 수준

**Level A — 실제 데이터 중심**

- 원본 RFP 3건: 사용자가 원본 여부 확인
- 나라장터 공고·첨부·낙찰정보: 공개 조달 자료
- 회사 역량 자료: 공식 웹사이트·한국거래소 공시 기반

한계: 낙찰 기록은 수주 사례이지 내부 Go/No-Go 정답이 아닙니다. RFP의 불필요한 연락정보는 검색·시연에서 가립니다.

## 5. RAG: 필요한 원문 근거를 찾아 검증에 사용

검색 입력: T1 추출 주장 + 정보 유형 + 공고번호/판본  
검색 대상: RFP·공고문·정정/재공고 첨부  
검색 결과: 문서·판본·페이지·조항·인용문

- 금액: 예산/추정가격, VAT, 총액/연차 검색
- 자격: 등록·제한·공동수급·예외 검색
- 기간: 수행기간·제안/입찰 마감 검색

## 6. 세 범주별 깊이 있는 검증

**사업금액**  
유형·총액/연차·VAT·단위 계산·문서 간 차이

**참가자격**  
적용 주체·요건·제한·공동수급·예외·관련 구간 누락

**기간·기한**  
수행기간·시작 기준·제안/입찰/공동수급 마감·날짜 충돌

각 범주에 별도 근거와 상태를 두며 회사 충족 여부는 T2가 평가합니다.

## 7. LangGraph: 상황에 따라 검색·검토를 분기

- **통과:** T1 → 세 범주 검증 → T2/T3 → 보고서
- **근거 부족:** 해당 범주만 RAG 추가 검색 → 재검증
- **충돌·불확실:** Human Review에서 확인 → 해당 항목 재검증 또는 보류
- 사람 확인 없이 자동 통과하거나 최종 Go/No-Go를 결정하지 않음

State: 문서 판본, 추출 주장, 범주별 근거·상태, 재검색 횟수, 사람 확인, 후속 결과

## 8. 기술 선택과 구현 순서

- LangGraph: 단일 workflow 제어
- LlamaIndex: RAG 검색 계층 후보
- 기존 PDF 추출기·Python 도메인 코드 재사용
- CrewAI: MVP 실행 경로에서는 미사용, 기존 코드는 보존

문서/판본 인덱싱 → 범주별 검색 → 검증·분기·HITL → 분석/UI 연동 → 품질 점검

역할 슬롯: 문서·RAG / 금액 / 참가자격 / 기간 / LangGraph·통합

## 9. 품질 평가와 한계

금액·자격·기간별로 따로 기록:

- 근거 검색 및 인용 정확성
- 필수 정보 누락과 문서 간 충돌 처리
- 근거가 부족한데 자동 통과한 사례

회사의 실제 증빙과 법적 해석은 사람이 확인합니다. AI는 근거를 찾아 정리하고, 최종 참여 결정은 담당자·본부장이 합니다.

**기대 결과:** 검증된 정보만 후속 분석에 전달하고, 불확실성은 숨기지 않고 담당자에게 연결
