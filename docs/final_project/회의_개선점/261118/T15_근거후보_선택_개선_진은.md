- 비교 기준: `62ca66c`의 T1.5 추가 검색 처리
- 상태: 코드 수정, 회귀 테스트 10개, 실제 PDF 3개 기반 키워드·벡터 검색 및 T1.5 연결 검증 완료. 전체 시스템 통합·정확도 평가는 별도.

## 기존 동작과 변경

기존 `reverify_after_retrieval()`는 미확인 항목의 검색 후보 중 `matches[0]` 하나를 바로 인용했다. 첫 후보가 목차·작성 안내인 경우, 뒤쪽 본문에 실제 값이 있어도 선택하지 못했다.

이제 검색 후보의 chunk ID와 동일 본문 중복을 제거한 뒤, 항목별 원문 내용을 규칙으로 비교해 최대 3개를 선택한다. 2개 이상을 무조건 채우는 방식은 아니다. 적절한 후보가 1개이면 1개, 없으면 미해결 상태를 유지한다.

1. **금액**: 대상 금액 항목 가까이에 원 단위로 읽을 수 있는 금액이 있는지 확인한다. 다음 항목 레이블에서 문맥을 끊어 사업예산과 추정가격을 섞지 않도록 한다. T1과 다른 수치도 검토 후보로 남긴다.
2. **일정**: 해당 일정 항목에 유효한 날짜 또는 계약의 상대 수행기간이 있는지 확인한다. 제출기한과 계약기간을 구분한다.
3. **참가조건**: 검색 주제뿐 아니라 등록·제한·허용·제출 등 구체적인 조건 문구가 있는 후보를 우선한다. 부정 표현과 예외를 포함한 원문을 그대로 인용한다.
4. 목차 줄을 제외하고 서식·작성 안내가 섞인 후보의 순위를 낮춘다. 서로 척도가 다른 BM25 점수와 벡터 유사도를 직접 비교하지 않는다.
5. 선택 이유를 검증 결과의 `targeted_retrieval_hit` 상세에 남기고 문서·페이지·출처를 보존한다.

## 사람 검토와 팀원 작업 범위

- 추가 검색 근거는 기존처럼 `human_review`로 연결한다. T1 값을 자동으로 바꾸거나 `confirmed`로 승격하지 않는다.
- 관련 값·조건을 찾지 못한 후보는 인용하지 않는다. 해당 항목은 `retrieve_more`로 남으며, 기존 재검색 한도 이후 사람 검토로 연결된다.
- 그래프 Node·Edge·승인/재개 방식, T2·T3·T4, 금액 기준, VAT 환산, PDF 추출 방식은 변경하지 않았다.
- `workflow.py`의 변경은 import와 `reverify_after_retrieval()` 내부에 한정했다. LangGraph 담당자 통합 시 이 블록을 보존하면 된다.

## 한계와 다음 확인

이는 LLM의 의미 판단이 아닌 규칙 기반 후보 선별이다. 원문 레이블이 사전에 없는 표현이거나 금액 단위·표가 여러 chunk에 흩어진 경우는 놓칠 수 있다. 선택된 후보가 법적·사실적으로 맞다는 보장은 없으며 담당자 검토를 유지한다.

실제 RFP 3개와 공고문 2개로 989개 chunk의 키워드·의미 검색 색인을 구축해 아래와 같이 연결 검증했다. 신규 나라장터 API 조회, T2~T4 전체 보고서 실행 및 별도 정답 표본의 정확도 평가는 이 검증에 포함하지 않았다. T3 과거 사업 프로필 정리는 별도 문서 `T3_과거사업_본문추출_개선_진은.md`에 기록했다.

## 추가: 실제 문서 연결 검증 (2026-11-19)

이 절은 위의 고정 테스트 입력과 별개로 실제 파일을 사용한 검증이다.

- 실제 RFP: 통합정보시스템, 상수도관 AI·GIS, 의료 CDW의 기존 PDF 3개
- 함께 검색한 공고문 PDF: 통합정보시스템·상수도관 2개
- 원본 SHA-256을 대조하고 나라장터 공개 첨부와 일치하는 자료임을 확인했다. 기존 개인정보 필터 후 전화·이메일 및 API 키 형태 검사 결과는 각각 0건이었다.
- 키워드 색인 989개 chunk와 실제 `text-embedding-3-small` 1,536차원 벡터를 생성했다.
- 실제 T1 추출값으로 T1.5 초기 검증 → 추가 검색 → 수정 전후 재검증을 실행했다. 같은 원문·색인에서 기준 커밋의 추가 검색/첫 후보 선택과 현재 코드를 비교했다.
- 실제로 추출한 T1 결과를 재사용해 LangGraph 라우팅도 확인했다. 신규 나라장터 조회는 사용 불가 상태로 명시했고 T2~T3는 실행하지 않았다. 세 사례 모두 `human_review_required`로 종료됐다.
- 추가로 범주별 검증을 위해 미확인 상태를 명시적으로 설정한 9개 항목(3문서 × 금액·기간·참가조건)을 실제 검색 색인에 연결했다. 이 9개는 자연 발생 오류 9건이라는 뜻이 아니다.
- 선택된 추가 인용의 문서·페이지·본문이 실제 색인 원문과 일치하고, 추가 인용은 최대 3개이며, 검색만으로 `confirmed`가 되지 않음을 확인했다.

### 실제 검증에서 발견해 보완한 부분

1. **기간의 원문 레이블 차이**: 기존 검색 질문의 ‘계약기간·수행기간’만으로는 ‘사업기간·과업기간·용역기간’의 실제 본문을 놓쳤다. 이 별칭을 추가 검색과 후보-항목 연결 양쪽에 동일하게 적용했다.
2. **값 없는 기간 문구**: ‘계약일로부터 사업종료일까지 월간 보고’처럼 시작 사건만 있는 일반 안내는 실제 날짜/기간 후보로 채택하지 않도록 했다. 절대 날짜 또는 숫자·단위가 있는 기간이 필요하다.

이 두 상황에 대한 회귀 테스트를 추가해 T1.5 테스트는 8개에서 10개가 됐다. 실제 원문에서 통합정보시스템 RFP의 2027-02-15, 상수도관 RFP의 2027-12-30, CDW의 2030-12-31이 선택 후보에 포함되는지도 확인했다. 공고문과 RFP의 날짜 차이를 자동으로 해결하거나 T1 값을 덮어쓰지는 않는다.
