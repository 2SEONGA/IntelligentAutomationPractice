### 3.2 T2·T3 평가 상시 보류 수정

- `agent23_evaluation.py`: 보류 사유가 아닌 참고 상태 `info`를 두었다.
  - 임베딩 유사도 주의사항(모든 후보에 붙음) → `info`
  - 검색 정상·임계값 이상 후보 없음(`none_above_threshold`) → `info`
  - 검색 실패·출처 불일치·법인 불일치·낙찰 연결 불명은 그대로 `needs_review`(보류)
  - `info`는 보고서의 "T2·T3 근거 평가"에 계속 표시된다(통과가 아닌 항목만 표시하는 기존 규칙).
- `past_projects.py`: 색인에 `award_notice_id`(낙찰 공고번호·차수)와 `award_source_url`(같은 공고번호의 나라장터 상세)을 넣었다. 재공고 묶음에서는 낙찰·공고번호·출처를 같은 공고에서 가져온다.
- 평가 규칙: 낙찰 공고번호가 후보와 같은 공고번호(차수는 달라도 됨)이고 출처 URL이 있을 때만 통과. 다른 공고번호의 낙찰은 보류. 실제 색인 22건 모두 통과.
- 테스트: `test_agent23_evaluation.py` 10 → 11개. 보류 표시·변조 검출 테스트 2개는 "후보 없음 = 보류"에 기대고 있어, 실제 보류 사유(법인 불일치)를 넣도록 입력을 바꿨다.

### 3.3 T3 임계값 재평가 준비

- 판정표: [`T3_임계값_재평가_판정표.md`](T3_임계값_재평가_판정표.md) (시연 3건 × 0.60 이상 최대 10건)
- **새 본문 기준 상수도관에 0.70 이상 후보가 10건**이다(M30·M31은 0건). 바다로시스템·신용평가모형 등 업무 분야가 다른 사업이 대부분이다. 새 본문에서 점수가 전반적으로 올라 0.70이 너무 낮아졌을 가능성이 크다. 판정 전까지 T3 결과는 참고로만 쓴다.
- 확인 필요 목록 대조: 송하연 점검 스크립트의 오류 13건 = 색인 확인 필요 12건 + 수의계약이라 원래 빠지는 1건(R26BK01754581). 본문이 짧은 9건 중 5건(316~437자)은 색인에 들어가 있으니 판정 때 함께 본다.
- 새마을금고(R26BK01589082)는 계약서만 저장돼 있어 올바른 RFP를 받아야 한다. 수집기는 저장된 폴더를 건너뛰므로 폴더를 지우고 다시 받아야 한다.

### 3.4 보완 7 토큰 측정 범위

LangGraph 경로는 LLM을 호출하지 않는다(T1·T1.5·T2·T4는 규칙 기반, T3은 임베딩, `BidReviewCrew`는 회사 자료 로드만). 그래서 임베딩 입력 토큰이 이 경로의 토큰 전부이고, 출력 토큰은 구조상 0이다. 코드는 그대로 두고 이주안 07 문서에 기록했다.

### 3.5 시나리오 로그 저장

`tests/test_workflow_scenarios.py`가 사례마다 `outputs/workflow_scenarios/<테스트명>.json`을 남긴다. 실행 이력(Node·상태·소요 시간), 중단 지점, `routing_plan`, 재검색 횟수, 검증·보고서 상태, 담당자 기록이 들어간다. 예: 근거 부족 사례 = `t1_extract → g2b_notice_lookup → t15_verify(retrieve_more) → t15_route → targeted_retrieval → t15_reverify(retrieve_more) → t15_route(human_review) → human_review`.
