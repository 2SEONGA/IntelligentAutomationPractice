### 3.2 T2·T3 평가 상시 보류 수정

**수정 1 — 표 병합 셀 (`agent01_rfp.py` `_table_rows`):** pdfplumber는 병합 셀이 덮은 칸을 `None`으로 준다. 셀 좌표로 위 셀이 그 행까지 세로로 이어질 때만 값을 채워 상위 구분을 행마다 남긴다(가로 병합 칸은 비움, 셀 안 세로쓰기 줄바꿈은 한 줄로). 예: 상수도관 26쪽 → `기술 능력 평가 (90점) | 정량 평가 (20점) | 경영상태 | ∘ 신용평가 등급 | 2 | 사업부서 평가`. 처음 시도한 "윗칸 단순 복사"는 가로 병합 칸(가격평가 옆)에 "정성평가"를 잘못 채워 버렸다.

**수정 2 — OCR 오탐 (`_ocr_reason`):** 표지·목차·별지 서식 쪽은 반복 문자·기호 비율로 "깨짐" 판정하지 않는다(목차는 짧은 글자 수도 제외). 시연 RFP 10쪽 → 0쪽, 과거 RFP 133건 8,704쪽 기준 769쪽 → 327쪽.

**수정 3 — OCR 설정 (`ocr.py`, `settings.yaml` `rfp.ocr.psm: 4`):** tesseract 기본 페이지 분할(psm 3)은 박스·표 레이아웃을 잘게 쪼갰다. 한 단 문서로 읽는 psm 4 + 흑백 변환으로 바꿨다.

OCR 실측 (tesseract 5.5.4 + kor, 300dpi, 시연 RFP 176쪽, PDF 내장 텍스트를 정답으로 비교):

| 설정 | 글자 일치율(중앙값) | 금액·날짜 보존 | 쪽당 시간 |
|---|---:|---:|---:|
| psm 3 (기본값) | 0.314 | 9/21 (43%) | 3.8초 |
| **psm 4** | **0.914** | **19/21 (90%)** | 3.3초 |

- psm 4에서도 PDF 내장 텍스트보다 낫지 않다. 모든 쪽을 비교하는 `always` 모드였다면 9쪽(주로 목차·표지)에서 정상 텍스트를 OCR로 바꿨을 것이다. → 기본 `fallback` 유지가 맞다.
- 색인 재생성: 청크 399개, Recall@3 0.927 · Precision@3 0.37 유지. 인용 정확도는 표 행이 셀 조합이 되면서 한때 0.847로 떨어져, 표 행은 셀마다 그 쪽 원문에 있는지 보도록 평가를 바꿨다(1.0). 이전 색인: `outputs/rag/backup_before_table_fill_261119/`.
- 테스트: 기존 OCR 테스트 3개는 오탐 쪽을 OCR 대상으로 가정해 `always` 모드로 같은 경로를 검사하도록 바꿨다. 병합 셀·오탐 0건 회귀 테스트 2개 추가.
- 이 PC에 tesseract·`pytesseract`를 설치했다. 다른 PC는 `brew install tesseract tesseract-lang` 후 `pip install -e ".[ocr]"`.

**남은 일 (송하연):**
1. 글자가 두 번씩 찍힌 PDF("요요구구사사항항", 굵은 글씨를 겹쳐 찍은 경우) — 과거 RFP 2건 76쪽. 겹친 글자 걸러내기로 처리 가능.
2. "별첨·별표·양식" 표식 서식 쪽이 서식으로 분류되지 않음(현재 표식: 별지·서식·붙임·첨부). 분류를 바꾸면 T1 추출 대상이 달라지므로 시연 3건 결과를 비교하며 넣는다.
