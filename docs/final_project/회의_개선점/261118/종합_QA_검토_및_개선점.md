### 문서 서술 중 지금 코드와 다른 점

- **"T1: LLM 정형 추출"**: T1은 규칙 기반이다. LangGraph 경로(T1·T1.5·T2·T4)에는 LLM 호출이 없고, T3만 임베딩을 쓴다(`보완사항_점검결과.md` 3.4).
- **아키텍처도의 T2→T3 직렬**: 병합 후 `workflow_mode="parallel"`(T2·T3 동시 실행)이 있다. 기본값은 순차다.
- **HITL "담당자 검토 대기"**: 병합 후 LangGraph에는 실제 중단·재개가 있다. 다만 웹에서는 아직 쓰지 않는다(2번).
- **"Re-ranker로 0.42 → 0.80 이상"**: 근거 없는 목표치다. 현재 문서 검색은 Recall@3 0.927 · Precision@3 0.37이다. 문제가 큰 곳은 T3 유사 사업 검색이다(아래 6번).
- **"체크리스트 연결만 보완하면 결점 없음"**: 오늘 실제 실행에서만 버그 1건(법인명 검사 상시 보류, 수정 완료)과 보고서 표시 누락 2건이 나왔다. 실제 자료 실행을 더 해야 한다.

## 3. T2·T3 병렬 구조 성능 비교 (앞으로 할 일)

### 3.1 현재 상태

- **구현은 끝났다.** 이주안 보완 7: `create_bid_review_graph(workflow_mode="parallel")`가 T1.5 이후 `analysis_fork`에서 (회사 근거 검색 → T2 매칭)과 (T3 유사 사업 검색)을 동시에 시작하고, 둘 다 끝나면 `t23_evaluate`로 합류한다. 동시 기록 충돌은 `execution_history` reducer로 처리했다. 비교 도구 `scripts/compare_workflow_modes.py`, 테스트 `tests/test_parallel_workflow.py`가 있다.
- **실제 비교는 한 번도 못 했다.** 비교 스크립트는 `run_bid_review`(종료형)를 부르는데, 실제 공고는 대부분 T1.5에서 담당자 검토로 멈춰 T2·T3까지 가지 않는다(상수도관도 그랬다). 지금 돌리면 두 모드 모두 T1.5에서 끝나 비교할 구간이 없다.

### 3.2 예상 효과 (실제 1건 실측 기반)

상수도관 실제 실행(`real-sangsudo-261119b`)의 Node별 시간:

| 구간 | 시간 |
|---|---:|
| T1 추출 | 4.20초 |
| 나라장터 조회 + T1.5 | 0.89초 |
| **T2** (회사 근거 검색 1.00 + 매칭 0.04) | **1.04초** |
| **T3** 유사 사업 검색 | **1.74초** |

- 같은 실행에서 `t23_evaluate`가 7.6초로 가장 크다(2장 5번). **속도 개선 효과는 병렬화보다 이쪽이 크다.** 비교 계획에 함께 넣는다.

## 4. 진행 결과: 체크리스트 K2·K3 자동 판정 (2026-11-20)

- `checklist.evaluate(..., core_review=None)`: 웹이 저장한 T1.5 결과(`langgraph_review.json`)를 받는다. 없으면 기존처럼 "확인 필요".
- **K2 대기업 참여제한:** T1.5의 나라장터 금액 교차검증(`g2b_crosscheck_budget_krw` 또는 `…_estimated_price_krw`)이 `confirmed`일 때만 판정한다. 나라장터 금액을 기준 VAT로 환산(`notice_filter.normalized_amount`)해 하한(체크리스트 `K2.min_amount_krw` 40억, `amount_vat_basis: included`)과 비교한다. 미만 → 미충족. 이상 → 충족. 단, 이상인데 공고에 "대기업 … 제한" 조항이 있으면 예외 인정 여부를 사람이 보도록 확인 필요.
- **K3 공동수급·지역·참여 법인:** `g2b_joint_contract`가 `confirmed`이고 나라장터 지역 제한 필드(`rgnLmtBidLocplcJdgmBssNm`, `cmmnSpldmdCorpRgnLmtYn`, 지역 의무공동도급 필드)가 비어 있으면 충족(단독 참여 전제, 하도급 제한은 원문 확인으로 근거에 표기). 지역 제한이 있거나 의무 공동수급이면 확인 필요.
- 기준 금액은 체크리스트 설정에 두어 결재 기준 스냅샷(`criteria.snapshot`)과 함께 보존된다. 담당자 수정(`apply_overrides`)이 계속 우선한다.
- 상수도관 실제 결과: **K2 미충족**("나라장터 배정예산 환산 1.18억 원(VAT 포함, RFP와 일치) < 대기업 참여 하한 40억 원 · 공고 조항: '대기업 참여 제한 사업임'"), **K3 충족**("공동수급 '(없음)공동수급불허'(나라장터·RFP 일치), 단독 참여와 충돌 없음 · 지역 제한 표시 없음"). 체크리스트 1단계 결과가 "보류"에서 **No-Go**로 바뀐다.
- 테스트: `test_checklist.py`에 경계·불일치·지역 제한·의무 공동수급·결과 없음·담당자 수정 우선, 실제 상수도관 결과 검사 추가.
- 한계: 웹에서 핵심정보 검토(T1.5)를 실행한 건에만 적용된다. 웹 첫 실행이 CrewAI 경로인 문제(2장 2·7번)는 그대로다.

## 5. 진행 결과: 보고서 표에 나라장터 값 반영 (2026-11-20)

- `report_nodes.g2b_overview()`: 나라장터 공고 조회값에서 발주기관(`dminsttNm`)·입찰 마감(`bidClseDt`)·공고 상세 URL을 뽑아 `report_details.g2b_overview`에 둔다. RFP 요약(`project_summary`)은 덮어쓰지 않는다(보고서 검증이 앞 단계 값과 정확히 대조하기 때문).

## 6. 진행 결과: 웹 핵심정보 검토를 중단·재개 실행기로 교체 (2026-11-20)

- `POST /api/runs/{id}/core-review`:
  - `analyze` → `hitl_runtime.start_review()`로 새 실행(`thread_id = web-…`)을 시작한다. 담당자 검토에서 멈추면 결과에 `hitl = {thread_id, status, interrupt_id}`를 저장하고 `decision = human_review_required`로 둔다.
  - `approve_and_run_t2` / `reject` → 저장된 중단 지점에서 `hitl_runtime.resume_review()`로 이어 간다. **T1을 다시 실행하지 않는다.** 검토자·사유는 그래프의 `review_history`에도 남는다.
  - 오래된 중단 지점, 실행 뒤 바뀐 입력 파일은 실행기가 거부하고 409로 돌려준다. 예전 방식으로 저장된 검토는 "검증을 다시 실행해 주세요"로 안내한다.
  - 화면이 쓰는 필드(`decision`, `verification`, `human_override`, `review_note`)는 그대로라 프론트엔드는 바꾸지 않았다.
- **함께 찾은 기존 버그:** 첫 검증은 공고번호를 이전 검토 결과에서만 읽어서, 웹에서는 나라장터 조회가 항상 생략됐다(`not_requested`). 공고함에서 시작한 건에 저장되는 `notice_attachment.json`의 공고번호·차수를 쓰도록 고쳤다. 직접 업로드한 건은 지금도 공고번호가 없어 조회를 건너뛴다.
- 실제 확인(테스트 클라이언트 + 상수도관 PDF·공고문): 검증 7.3초 → 중단(나라장터 조회 `found`), 승인 11.6초 → T4 완료. 실행 이력에서 `t1_extract`는 1회. 체크리스트 K2 미충족·K3 충족 → 1단계 No-Go, 권고 "No-Go 권고".
- 테스트: `test_app.py`에 중단 저장·승인 재개·T1 재실행 없음·사유 필수·중복 승인 409·입력 변경 409·공고번호 전달 검사 추가.
- 남은 일: 웹 첫 실행(`run.py`, CrewAI)을 LangGraph로 바꾸는 일원화(2장 7번). 화면에서 담당자 "수정(edit)" 응답은 아직 쓰지 않는다(승인·반려만).
