## 문제와 수정 범위

기존 코드는 앞 12쪽/블록에서 ‘사업 개요·목적·범위’라는 표현이 있는 페이지 전체를 이어 붙이고 처음 2,500자를 사용했다. 점선·쪽 번호가 없는 목차나 계약서의 일반 조항도 검색용 사업 본문에 들어갈 수 있었다.

이번 수정은 **프로그램 규칙으로 실제 사업 설명을 고르는 전처리 개선**이다. LLM에게 문서를 읽히거나 새로 요약시키지 않는다. 벡터 변환은 기존처럼 OpenAI `text-embedding-3-small`을 사용한다.

## 변경한 처리

1. 앞 24쪽/블록 안에서 사업 개요·배경·목적·범위의 제목과 실제 설명을 함께 확인한다. HWP/HWPX의 ‘블록’은 기존 방식인 50줄 단위이며 물리적인 쪽 번호가 아니다.
2. 페이지 전체 대신 해당 제목 아래의 본문을 선택한다. 다음 사업 절을 이어 검토하되 계약조건, 입찰절차, 제출서류, 제안서 작성 안내, 공통 요구사항 분류 안내 등이 시작되면 해당 구간 선택을 멈춘다.
3. 번호 없는 목차, ‘제목 + 쪽 번호’ 목차, 서식·심의결과 문구, 반복 글자 때문에 훼손된 줄을 걸러낸다. 연락처 제거는 기존 개인정보 필터를 재사용한다.
4. 제목 아래에는 중복을 제외한 설명이 80자 이상 있어야 한다. 명확한 제목이 없는 자료는 서로 다른 기술 설명 문단이 2개 이상이고 총 160자 이상인 경우에만 보조 경로로 선택한다. 이 길이 기준은 품질 보조 규칙이며 정확도 평가로 확정된 기준이 아니다.
5. 계약/서약 양식으로 식별되는 첨부는 수집 후보와 색인 대상에서 제외한다. RFP와 계약조건이 합쳐진 문서는 본문을 확인할 수 있도록 유지한다.
6. 적절한 본문이 없거나 읽기 오류가 있으면 원본을 보존하고 `outputs/rag/past_projects_review.json`에 확인 필요 사유를 남긴다. 임의의 앞부분을 대신 벡터화하지 않는다.
7. 확인한 본문으로 과거 사업 벡터를 다시 생성한다. 검색 때 과거 사업 전체를 매번 다시 벡터화하는 방식은 아니다.

## 실제 원문 전후 비교

### 경북도청신도시 스마트도시 건설사업(2차)

- 공고: `R26BK01530630-001`
- 원문: `붙임2. 제안요청서(정정공고).hwpx`
- 개선 전 시작: ‘사업개요 / 1. 사업명 / 2. 사업의 배경 및 목적 / 3. 사업기간 …’이라는 목차 제목 목록
- 개선 후 시작: ‘2. 사업의 배경 및 목적 / 경북도청 신도시는 도시 규모 확대와 인구 증가에 따라 교통·안전·환경 등 도시 운영 전반에 대한 관리 수요가 지속적으로 증가하고 있으며 …’
- 확인: 실제 배경·목적과 스마트도시 서비스 범위가 추출된다. 원문 파일은 수정하지 않았다.

### 새마을금고 계정계 최신화 구축

- 공고: `R26BK01589082-000`
- 저장된 첨부: `2. 계약서(새마을금고 계정계 최신화 구축).hwp`
- 개선 전 시작: ‘③ “을”은 “갑”으로부터 제13조 또는 제14조의 최종 검사 완료 통보를 받은 경우 …’라는 계약 조항
- 개선 후: 계약서 첨부로 구분해 벡터화 보류, 올바른 제안요청서 확인 필요로 기록
- 확인: 이 자료는 추출 규칙만으로 사업 설명을 복구한 것이 아니다. 올바른 RFP 확보가 남아 있다. 기존 수집기는 이미 저장된 폴더를 건너뛰므로 단순히 수집 명령을 다시 실행하는 것만으로 교체되지는 않는다.

### 정상 본문 유지 확인

- KDB Paperless: 목차의 별첨·서식 목록을 건너뛰고 전자문서 기반 업무체계 전환과 AX·DX 추진 배경이 선택된다.
- 중견기업 종합정보시스템 유지보수: ‘1 추진배경’처럼 점 없는 번호 제목도 인식하여 실제 운영·유지보수 설명을 선택한다.

## 전체 자료 확인 및 실제 재색인

| 항목 | 결과 |
|---|---:|
| 원본 파일 SHA-256 대조 | 152개 일치 |
| 개선 전 검색 대상 사업 / 공고 | 112개 / 130건 |
| 개선 후 검색 대상 사업 / 공고 | 101개 / 118건 |
| 기존 수의계약 제외 | 16건 |
| 확인 필요로 기록한 공고 | 13건 |
| 확인 필요 구성 | 계약/양식 첨부 4건, 본문 부족·추출 품질 문제 8건, PDF 읽기 오류 1건 |
| 실제 벡터 | 101 × 1,536차원, 행 대응·유한값·정규화·본문 해시 확인 |
| 낙찰 연결 | 22개 사업 |

공고 차수와 같은 사업의 재공고를 묶으므로 ‘152개 파일’, ‘공고 건수’, ‘사업 개수’는 서로 다르다. 검색 대상 감소는 확인되지 않은 자료를 보류한 결과다. 원본 삭제나 수집량 감소가 아니다.

분석 중 확보한 원문 추출 사본은 원본 152개의 다운로드 SHA-256과 일치하는지 확인한 뒤 전후 비교와 재색인에 재사용했다. 실제 검색 벡터는 가짜 임베딩이 아니라 본인 키로 임베딩 API를 호출해 생성했다.

## T3 단독 검색 확인

기존 `data/input` PDF 세 개에 대해 새 규칙으로 검색 질의를 만들고 실제 벡터 검색을 실행했다. 현재 공고 제외, 최대 5건, 0.70 이상 조건을 확인했다. 전체 LangGraph/CrewAI 보고서 실행을 완료했다는 의미는 아니다.

| 입력 | 최상위 후보 | 유사도 |
|---|---|---:|
| 통합정보시스템 고도화 구축 용역.pdf | 통합정보시스템 고도화 구축 용역 | 0.9905 |
| AI 영상 기반 상수도관 노후도 분석 및 GIS 연동 소프트웨어 개발 용역.pdf | 차세대 바다로시스템 구축 | 0.7821 |
| AI의료 기술 개발 고도화 관련 임상연구정보검색시스템(CDW) 구축.pdf | AI 의료 기술 개발 고도화 관련 다기관 임상데이터 연계⦁검증(Dataset) 구축 사업 | 0.9216 |

**해석 주의:** 상수도관 사례에서는 공통 기술·정보시스템 표현이 겹치지만 상수도관·GIS와 직접적인 연관이 약한 다른 업무 분야의 사업도 후보로 나온다. 높은 유사도를 곧바로 같은 분야의 적합한 유사사업이나 실적으로 해석하면 안 된다. 이번에 확인한 개선은 본문 선택과 부적절한 자료 보류이며, 세 사례 검색 결과 전체의 정확도가 향상됐다는 주장은 하지 않는다. 본문이 바뀌어 점수 분포도 달라졌으므로, 기존 M25의 0.70 기준 성능을 그대로 적용할 수 없다. 업무 분야 적합성과 임계값을 별도 정답 표본으로 재평가해야 한다.
