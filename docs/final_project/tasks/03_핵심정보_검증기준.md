# Task 03 — T1.5 핵심정보 증거 검증 기준

상태: 완료 — 사용자 확인 반영  
작성일: 2026-11-11

## 목표

T1의 추출 결과를 T2·T3 및 보고서에 전달하기 전에 별도 검증한다. 금액·참가자격·기간을 각각 깊이 있게 확인하고, 근거가 부족하거나 충돌할 때 그 사실을 숨기지 않고 추가 검색 또는 담당자 검토로 보낸다.

## 공통 검증 계약

검증 T는 정보마다 다음을 보존한다.

| 필드 | 의미 |
|---|---|
| `claim` | T1이 추출한 값 또는 조건 |
| `claim_type` | 금액·자격·기간 안에서의 세부 유형 |
| `source_refs[]` | 문서 ID, PDF 페이지, 원문 인용 구간 |
| `verification_checks[]` | 적용한 유형별 검사와 검사 결과 |
| `status` | `confirmed`, `retrieve_more`, `human_review`, `conflict` |
| `reason` | 통과하지 못한 구체적 이유와 남은 질문 |
| `alternatives[]` | 원문에 함께 나타난 후보 값·조건 |

통과는 “이 정보가 모든 법적·사업적 판단에 충분하다”는 뜻이 아니다. 해당 추출 주장과 원문 근거가 일치하고, 그 범주에서 필수 정보가 빠지지 않았음을 확인했다는 뜻이다. T1.5는 공고/RFP에 참가자격 조건이 무엇이라고 쓰였는지를 검증한다. 회사가 그 조건을 만족하는지 대조하는 역할은 기존 T2에 두고, 법적 적용과 최종 입찰 가능성은 사람이 판단한다.

### 독립성 원칙

- T1의 필드 값만 다시 읽고 승인하지 않는다. 검증 노드는 RAG 검색으로 원문 페이지·주변 문맥을 다시 찾아 직접 대조한다.
- 같은 추출 산출물을 자기 자신의 증거로 재사용하지 않는다. 증거는 원본 RFP·공고문 또는 허용된 1차 출처에서 가져온다.
- 유사 문장 검색 결과가 없다는 이유만으로 조건이 없다고 결론 내리지 않는다. 완전성 확인이 필요한 범주는 해당 장·표·부록의 탐색 범위를 기록한다.
- LLM의 자연어 판단과 분리 가능한 금액 산술·날짜 순서·필수 필드 검사는 결정론적 규칙으로 확인한다.
- AI 검증과 T1 추출이 서로 같은 값을 말하는 것만으로는 통과하지 않는다. 양쪽 결과가 원문 근거에 연결돼야 한다.

## 1. 사업금액 검증

### 추출·대조 항목

- 원문 표기와 정규화된 원화 정수 값
- 금액의 의미: 사업예산/사업금액/추정가격/기초금액 등
- 범위: 전체 계약 총액/연차별 금액/세부 과업 또는 선택 항목
- VAT 포함·별도·표기 없음
- 다년 사업의 총 기간과 연차별 집행 표현
- RFP와 공고문에 각각 적힌 값 및 각 문서의 출처

### 통과 기준

- 금액 숫자와 금액 레이블이 같은 원문 구간 또는 연결된 표 행에서 확인된다.
- 원문 표현의 단위 계산 결과와 정규화 값이 일치한다.
- 서로 다른 후보가 있다면 총액·연차별·추정가격 등 의미 차이가 구조화돼 있고, 보고서가 이를 혼동하지 않는다.
- 판단에 필수인 VAT·기간 조건이 명시되어 있거나, 미기재 상태가 명확히 기록된다.
- 다른 문서 값과 충돌이 없거나, 충돌이 있으면 해결 경로가 정해져 있다.

### 재검색·사람 확인 조건

- 레이블과 숫자가 분리돼 있거나 표 열 관계가 모호함 → 관련 표 페이지와 앞뒤 문맥 추가 검색
- 총액과 연차별 액수를 구분할 수 없음, VAT 조건이 판정에 중요하지만 원문이 불명확함 → 담당자 확인
- RFP·공고문 금액 충돌 또는 공고 정정 가능성 → 최신 공고 및 정정 공고 확인 후 사람 승인
- 한글 숫자·단위 변환 결과와 원문이 불일치 → 자동 통과 금지, 원문 확인

### 깊이 확인 사례

`3억 원`, `1.07억 원`, `10.7억 원`, 쉼표 단위 원화, VAT 별도, 5년 총액·연차별 집행, 추정가격과 사업예산 동시 존재, 본문·표 금액 충돌, 다른 사업의 금액이 같은 페이지에 등장하는 경우를 포함한다.

## 2. 참가자격 검증

### 조건 원자화

각 조건을 한 문장으로 뭉치지 말고 다음 슬롯으로 구조화한다.

- 적용 주체: 단독 입찰자, 공동수급체 전체, 구성원, 대표사, 하도급사
- 의무/허용/금지 및 조건의 강도
- 업종·면허·등록·실적·인증·기업 규모 등 조건 유형
- 적용 기준일·유효기간·요구 수치·인정 기간
- 공동수급·지역·하도급·대기업 참여 제한 및 예외
- 원문 근거와 별도 증빙 문서 필요 여부

### 완전성 기준

- 참가자격 장·입찰 방법 장·제안 안내·서식·부록 등 탐색해야 할 구간을 문서별로 기록한다.
- K1~K4에 대응해 법적 등록·참여 제한·공동수급/지역 조건·필수 인증/인력을 각각 확인 대상으로 삼는다. 해당 문서에서 언급이 없더라도 “문서 전체에서 확인되지 않음”과 “아직 검색하지 않음”을 구분한다.
- 조건 본문뿐 아니라 예외, 단서, “다만/단, 제외” 문구도 같이 검색해 연결한다.
- 서로 다른 문서나 장에서 조건이 바뀌면 하나를 임의 선택하지 않고 충돌로 기록한다.

### 통과 기준

- 요구 조건이 원문 인용과 페이지에 연결되어 있고 위 적용 주체·조건·예외의 해석이 구조화돼 있다.
- 조건을 빠뜨리지 않았는지 확인 범위가 기록돼 있다.
- 조건이 요구하는 입찰 제출용 증빙 종류(사업자등록·면허·인증서·실적증명·인력 증명 등)를 원문에서 추출한다. 실제 회사 증빙의 유무·충족 여부는 기존 T2가 평가한다.

### 재검색·사람 확인 조건

- 제한/예외 문구 또는 공동수급 구성원별 적용이 모호함 → 해당 조항과 관련 정의·서식 재검색
- 자격 조건 자체가 법률·지침의 적용 해석을 요구함 → 담당자 또는 법무 검토
- 회사 자료와 입찰 원본 증빙이 없거나 유효기간을 알 수 없음 → 담당자 확인
- 탐색한 문서 구간이 불완전하거나 표·스캔 페이지를 읽지 못함 → 자동 통과 금지

### 깊이 확인 사례

필수 업종 등록, 복수 면허, 공동수급 구성원 간 분담, 지역 제한과 예외, 대기업 참여 제한과 적용 기준, 실적 금액·기간 요건, 인증 유효기간, 인력 등급·경력 조건, 제출 서식의 추가 요건, 자격 문구가 부록에만 있는 경우를 포함한다.

## 3. 기간·기한 검증

### 날짜 유형

- 계약 수행기간: 시작 기준(계약일·착수일 등), 기간 길이, 종료일
- 입찰 일정: 입찰 등록·입찰서 제출·제안서 제출 시작/마감
- 공동수급 협정서 제출 마감
- 착수·중간·완료 등 수행 마일스톤

### 통과 기준

- 날짜 유형이 원문 레이블·문맥에 맞게 분류되어 있다. 제안서 마감일을 입찰서 마감일로 대체하지 않는다.
- 원문에 절대 날짜가 있으면 날짜·시간을 정확히 보존한다. 시간대가 원문에 없으면 임의로 보충하지 않는다.
- 상대 기간(예: 계약 후 18개월)은 기준 사건과 지속 기간을 함께 보존한다. 시작일이 없으면 임의의 달력 날짜로 계산하지 않는다.
- 날짜 형식 정규화 결과와 원문 날짜가 일치하고, 시작·종료 및 마감 순서에 모순이 없다.
- 날짜가 공고문·RFP 간 다르면 각 출처와 최신/정정 여부를 확인한다.

### 재검색·사람 확인 조건

- 표의 열 제목과 값 연결이 불명확함 → 표 전체와 주변 문맥 추가 검색
- 기준 사건(계약일/착수일)이 불분명하거나 “예정” 표현이 확정 일정처럼 추출됨 → 담당자 확인
- 날짜·시간이 서로 다르거나 정정 공고 여부가 불명확함 → 최신 공고 확인 후 사람 승인
- 시간대 또는 날짜 표기에서 추정이 필요한 경우 → 원문 확인 전 통과 금지

### 깊이 확인 사례

“계약 체결 후 30일”, “계약일로부터 5개월”, 절대 날짜+시각, 제출 시작과 마감이 같은 페이지 표에 존재, 공동수급 마감과 제안서 마감 분리, 연차별 수행 일정, 과거 공고와 정정 공고 간 날짜 차이를 포함한다.

## 전체 상태와 라우팅 규칙

| 조건 | 검증 결과 | 다음 처리 |
|---|---|---|
| 해당 범주의 필수 항목이 원문과 일치하고 미해결 충돌 없음 | `confirmed` | 해당 정보의 후속 분석 허용 |
| 관련 근거가 부족하지만 원문 안에서 추가 검색할 여지가 있음 | `retrieve_more` | RAG 검색어/범위를 보강해 재검색 |
| 두 개 이상의 유효 후보가 서로 다름 | `conflict` | 후보·출처를 보존하고 공고 정정 여부 및 담당자 확인 |
| 검색 한도 도달, 문서 추출 실패, 법률·업무 해석 또는 원본 증빙이 필요 | `human_review` | 해당 항목의 근거·질문과 함께 담당자 검토 |

상태는 항목별로 저장한다. 한 항목이 `human_review`여도 다른 항목의 근거 확인 결과는 지우지 않는다. 최종 입찰 Go/No-Go 권고는 필수 항목의 확인 필요 상태를 반영해 보류할 수 있으며, 검증 T가 법적 최종 결정을 내리지는 않는다.

## 깊이를 확인할 평가 자료

세 범주별로 별도 사례 표를 만든다. 각 사례에는 기대 추출값, 필요한 원문 증거 범위, 기대 상태, 이유, 잘못 통과했을 때의 영향이 포함돼야 한다. 최소 사례 유형은 정상·누락·충돌·문맥 오인·OCR/표 구조 손상이다. 각 범주 성능을 따로 보고하며 하나의 총점만으로 품질을 주장하지 않는다.
