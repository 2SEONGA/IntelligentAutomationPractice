# Task 06 — 구현 범위·기술·역할·일정 계획

상태: 계획 초안 완료 — 팀 협의가 필요한 이름·날짜는 미정으로 유지  
작성일: 2026-11-11

## 목표

13주차 계획 발표에서 학기 안에 구현 가능한 범위와 단계, 기술 역할, 팀 분업을 설명한다. 사용자 선택 A를 반영해 LangGraph를 단일 workflow orchestrator로 사용하고 기존 Python 도메인 기능을 재사용한다.

## 확정된 기술 방향

- **LangGraph:** 전체 workflow State, 조건 분기, 재검색, 사람 검토 중단·재개
- **LlamaIndex:** 수업에서 학습할 RAG 검색 계층 후보. 문서 연결·chunk 검색에 사용
- **현재 PDF 처리 코드:** pypdf/pdfplumber 페이지·표 추출을 우선 재사용
- **검색:** 원문 용어를 놓치지 않는 키워드 검색과 의미 기반 검색을 결합하는 방식
- **보관:** 소규모 로컬 문서 인덱스부터 시작. 벡터 저장소와 패키지 버전은 구현 전 공식 문서 확인 후 고정
- **LLM 사용:** 검색 근거와 T1 추출 주장의 의미적 대조에 사용하되, 산술·날짜 형식·필수 필드·출처 존재 여부는 결정론적 코드로 확인
- **CrewAI:** 기말 MVP 실행 경로에서는 사용하지 않는다. 기존 CLI·코드·프롬프트·설정은 보존한다.
- 현재 `pyproject.toml`에는 LangGraph와 LlamaIndex 의존성이 없다. 구현 시작 시 필요한 최소 패키지만 추가한다.

## MVP 범위

### 반드시 구현

1. 원본 RFP와 연결된 공고문/수정 첨부를 공고번호·차수·버전과 함께 관리한다.
2. 페이지·섹션·표 위치를 잃지 않는 문서 검색과 인용 가능한 RAG 근거를 만든다.
3. 사업금액·참가자격·기간을 별도 검증 항목과 범주별 기준으로 확인한다.
4. 증거가 부족하면 범주별 추가 검색을 수행하고, 충돌·모호·검색 실패는 Human Review로 보낸다.
5. 검증된 사실만 후속 T2/T3 분석에 보내고, 미확정 정보를 보고서에 표시한다.
6. 기존 웹앱에서 근거·검증 상태를 사람이 확인할 수 있게 연결하거나, 웹 통합이 과도하면 같은 결과를 보여주는 시연용 최소 화면/CLI를 먼저 완성한다.

### 이번 MVP의 범위 밖

- 나라장터 전체 공고 자동 수집의 운영 수준 개선
- 회사 인력의 실시간 가용성·실제 증빙 유효성 자동 판정
- 합성 문서 생성 또는 대규모 코퍼스 수집
- 여러 오케스트레이터를 중첩하는 실행 구조
- AI의 최종 Go/No-Go 결정

## 단계별 구현 마일스톤

| 순서 | 마일스톤 | 산출물/완료 조건 |
|---|---|---|
| M1 | 입력 문서·판본 정리와 인덱싱 | 페이지·표·섹션과 공고번호·버전이 보존된 로컬 RAG 인덱스, 민감정보 제외 규칙 |
| M2 | 세 범주의 claim/evidence 스키마와 검색기 | 금액·자격·기간 각각에 대해 질의·결과·페이지 근거가 다른 형식으로 보존됨 |
| M3 | T1.5 verifier와 LangGraph 라우팅 | 통과/추가검색/충돌/Human Review 분기가 작동하고 재검색 반복이 제한됨 |
| M4 | 기존 분석 흐름 및 시연 연결 | 확인 사실만 T2/T3로 전달, 원문 인용과 사람 확인 내역이 결과 화면 또는 보고서에 표시됨 |
| M5 | 범주별 품질 점검·발표 준비 | 각 범주의 정확성·인용·누락·오안전통과를 따로 기록하고 시연 흐름을 완주함 |

M1~M3가 완료되기 전에 전체 UI를 확장하지 않는다. 일정이 짧아지면 UI의 시각적 개선보다 세 범주 검증과 출처 인용을 우선한다.

## 팀 역할 슬롯 초안

팀원 이름과 선호를 확인한 후 배정한다. 업무는 한 사람이 구현한 뒤 다른 담당자가 범주별 근거·사례를 검토하도록 교차 리뷰를 둔다.

| 역할 슬롯 | 주 책임 |
|---|---|
| 데이터·문서 담당 | G2B 첨부 판본 확인, 개인정보 비노출, PDF/표 추출 및 인덱스 구축 |
| 금액 검증 담당 | 금액 의미·VAT·총액/연차·단위 환산·충돌 규칙 |
| 자격 검증 담당 | 조건 원자화·적용 주체·예외·완전성·문서 범위 점검 |
| 기간 검증 담당 | 수행기간/제출기한 분류·기준일·순서·버전 충돌 검사 |
| 그래프·통합 담당 | LangGraph State·라우팅·HITL 재개·기존 UI/보고서 연동 |

한 사람이 그래프와 문서 처리를 모두 맡아 병목이 되지 않도록 공통 모듈과 인터페이스를 먼저 합의한다. 팀원 수가 다르거나 강점이 겹치면 역할을 묶거나 나누되, 범주별 검증 리뷰 책임은 유지한다.

## 일정 초안

실제 제출·시연 날짜를 확인한 뒤 달력 주차를 넣는다. 그 전에는 다음 순서를 기준으로 작업량을 조정한다.

1. 자료 판본 확인, 문서 메타데이터, 공통 schema
2. RAG ingestion/retrieval과 citation 확인
3. 세 범주의 독립 verifier 작성
4. LangGraph 조건 분기와 Human Review 연결
5. 기존 T2/T3 결과 및 화면 연결
6. 세 범주별 시연과 품질 기록, 발표 자료 다듬기

## 미확정 선택

- 기존 웹앱과 결합할 범위: 검증 결과 탭을 붙일지, CLI 기반 시연으로 먼저 완성할지
- 회사 공개자료를 RAG 코퍼스로 넣을 시점: T1.5 원문 검증에서 제외하며, T2 RAG 확장에만 포함할지
- LlamaIndex + 로컬 벡터 저장소의 정확한 조합과 버전: 문서 원문 구조와 팀 환경 확인 뒤 선택
- 개인별 역할과 마일스톤 날짜: 사용자/팀 정보 대기

## 품질 확인 방식

자동화 코드의 평가를 한 숫자로 합치지 않는다. 금액·자격·기간별로 원문 근거 적중, 인용 정확성, 필수 정보 누락, 충돌 처리, 잘못된 자동 통과를 기록한다. 5주차의 기존 세 RFP는 실제 입력 사례로 쓰고, 문서에서 직접 확인 가능한 정상·오류 사례를 추가로 구성한다. 결과 산출은 사람이 원문과 대조해 확인한다.
