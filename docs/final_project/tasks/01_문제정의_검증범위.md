# Task 01 — 문제 정의와 검증 범위 확정

상태: 완료  
작성일: 2026-11-11

## 목표

기말 프로젝트에서 해결할 업무 문제, 업무의 시작과 종료, 핵심정보 검증 범위를 정한다. 교수님 피드백인 “T1과 T2 사이에 인식 정보가 정확한지 확인하는 검증 T”를 기존 파이프라인에 맞게 구체화한다.

## 현재까지 조사한 구성

- 기존 파이프라인은 RFP 분석, 역량 매칭, 시장 조사, 보고서 작성을 수행한다.
- T1의 금액 추출은 `src/bid_review/agent01_rfp.py`의 후보 수집·선택 로직에서 처리한다.
- `src/bid_review/money.py`는 한국어 금액 표현을 원 단위로 변환한다.
- `src/bid_review/project_scale.py`는 금액 후보 충돌, 페이지·발췌 근거 유무, 내부 최소 기준을 확인한다.
- `src/bid_review/crew.py`는 RFP와 공고문 분석 결과를 통합하고 기존 품질 게이트에 따라 후속 단계를 중단할 수 있다.
- 따라서 기존 코드에는 형식·후보·근거를 보는 검사가 일부 존재한다. 기말 설계에서 보완할 핵심은 금액 정보의 의미와 원문 일치 여부를 별도 단계에서 확인하고, 검증 상태에 따라 후속 처리를 분기하는 것이다.

## 문제 정의

> 공공 SI 입찰 검토에서 RFP와 공고문의 사업금액·참가자격·기간 정보를 원문 근거와 함께 추출·검증하고, 정보의 불일치·누락·불확실성을 추가 검색 또는 담당자 확인으로 연결해 잘못된 입찰 판단으로 이어질 위험을 줄인다.

## 업무 흐름 초안

- 시작: 담당자가 나라장터 공고 및 RFP·공고문 PDF를 시스템에 제공한다.
- 처리: T1이 핵심 정보를 추출하고 T1.5가 정보 유형별 기준으로 원문 근거와 대조한다. 근거가 불충분하면 RAG로 관련 페이지를 더 찾는다.
- 종료: 검증된 정보를 후속 분석에 전달하거나, 해결되지 않은 항목을 근거·사유와 함께 담당자에게 전달한다.
- 사람의 역할: 자동 추출 결과를 최종 사실로 간주하지 않고, 충돌·불명확한 근거 및 최종 입찰 판단을 확인한다.

## 검증 대상과 깊이 기준

각 범주에 단순 문자열 일치 이상의 전용 검증 기준을 둔다. 검증 결과는 `통과`, `추가 검색 필요`, `담당자 확인 필요`로 구분하는 것을 설계 기준으로 삼는다.

### 항목별 깊이를 보장하는 설계 원칙

- 세 범주를 하나의 포괄적인 “정확도 점수”로 뭉개지 않는다. 금액·자격·기간마다 별도 검증 결과와 근거 목록을 둔다.
- 각 범주에서 **추출된 주장 → 필요한 근거 → 근거와의 대조 규칙 → 예외·충돌 처리 → 라우팅**을 독립적으로 정의한다.
- 각 범주마다 정상·누락·충돌·문맥 오인 사례를 포함한 확인 시나리오를 준비한다. 한 범주의 통과가 다른 범주의 완료를 대신하지 않게 한다.
- 강한 원문 근거가 없거나 조건 의미가 모호하면 통과시키지 않는다. 근거 위치, 불일치 값, 남은 질문을 사람에게 보여준다.
- 구현은 순차로 진행해도 최종 범위에서 어느 범주도 얕은 요약 검사로 대체하지 않는다. 일정이 부족하면 완료 기준을 낮추지 않고 시연 사례 수와 주변 기능을 조정한다.

### 사업금액

- 추출 금액과 원문 발췌·문서명·페이지가 연결되는지 확인한다.
- 사업예산·사업금액·추정가격 등 금액의 종류를 구분한다.
- 부가세 포함 여부와 다년 사업의 총액·연차별 금액을 확인한다.
- RFP와 공고문에 금액이 있으면 값과 조건을 비교한다.
- 원문 표기와 원 단위 정규화 값이 일치하는지 확인한다.

### 참가자격

- 조건의 적용 대상(입찰자/공동수급체 구성원 등), 자격·등록 요건, 제한 조건, 예외를 각각 구조화한다.
- 공동수급, 지역 제한, 기업 규모 제한 등 별도 조건을 누락 없이 확인한다.
- 조건별로 원문 근거 위치를 연결하고, 자료에 명시되지 않은 회사 자격을 충족으로 추정하지 않는다.
- 공고문 확인이 필요한 조건과 회사 원본 증빙이 필요한 조건을 구분한다.

### 기간·기한

- 계약 수행기간, 제안서 제출기한, 입찰서 마감 등 서로 다른 날짜 유형을 구분한다.
- 기간의 시작 기준·종료일·연차 표현을 보존한다.
- 시간대·날짜 형식·문서 간 불일치와 누락을 확인한다.
- 마감일을 잘못 분류하거나 임의로 보정하지 않고, 모호하면 담당자 확인으로 보낸다.

세 범주 모두 충돌·누락·불명확한 의미가 있으면 자동 통과시키지 않는다. RAG 추가 검색 후에도 해결되지 않으면 근거와 미해결 사유를 붙여 담당자 확인으로 보낸다.

## 확정된 범위

사용자는 **금액·참가자격·기간 등 핵심정보 검증으로 확대하되 각 항목별 검증이 얕아지지 않도록 설계**하는 방향을 선택했다. 이에 따라 프로젝트 업무 맥락은 입찰 검토 전체로 유지하고, 검증 T는 세 범주별 명시적 기준과 증거를 갖도록 설계한다. 세 범주의 깊이를 보장하는 공통 원칙을 위에 기록했다. MVP 세부 범위는 데이터·일정 조사를 바탕으로 정하되, 일정이 부족하면 범주별 완료 기준을 약화하는 대신 시연 사례 수와 주변 기능을 조정한다.
