## 발표안 구성

1. 프로젝트 주제와 문제 정의
2. 업무 시작·종료 및 대상 범위
3. 기존 프로젝트와 5주차 오류 사례
4. 제안 시스템과 T1.5 검증 게이트
5. Level A 데이터와 출처·한계
6. RAG 검색 대상과 증거 활용
7. 금액·참가자격·기간별 검증 깊이
8. LangGraph State와 Conditional Routing
9. 기술 선택·마일스톤·역할 슬롯
10. 품질 평가·한계·기대 결과

발표 메모는 총 약 8분이 되도록 10장에 나눠 배정했다. 질문 예상과 답변도 문서에 포함했다.

## 발표에서 분명히 한 설계 결정

- 데이터는 Level A로 제시하며 원본 RFP 확인 주체와 공공 데이터 출처를 설명한다.
- 사업금액·참가자격·기간은 단일 점수로 합치지 않고 독립된 근거·검증 기준을 가진다.
- T1.5는 문서에 쓰인 조건을 검증하고, 회사가 충족하는지는 기존 T2가 대조한다.
- LangGraph가 단일 workflow owner이며 기존 CrewAI 실행은 MVP에서 제외하고 코드·데이터·Python 분석 모듈은 재사용한다.
- 검색 근거 부족·문서 버전 차이·사람 최종 결정의 경계를 발표에 포함한다.

## 미정 사항 표기

- 팀원 이름별 역할과 날짜별 일정은 팀 협의가 필요하므로 역할 슬롯과 순서형 마일스톤으로 표시한다.
- 로컬 프로젝트는 LangGraph/LlamaIndex를 아직 의존성으로 포함하지 않는다. 구현 전에 패키지와 벡터 저장소를 결정한다.
- PPT는 Pandoc 기본 테마로 생성했다. 학교/팀 템플릿·팀 로고·발표자 배정은 반영하지 않았다.
- 이 환경에서 슬라이드 렌더링 미리보기는 하지 못했다. 파일 내부에서 표지 포함 10개 슬라이드 구성을 확인했다.
