## 최종 데이터 Level

**Level A — 실제 데이터 중심**으로 발표한다. 사용자가 `data/input`의 세 RFP가 원본이라고 확인했고, 로컬 공고 데이터에서도 대응하는 나라장터 공고·첨부 링크를 찾았다. 보조 데이터도 공개 회사 자료와 나라장터 낙찰정보를 바탕으로 구성돼 있다. 현재 프로젝트의 핵심 입력에 합성 데이터를 사용한다는 근거는 확인하지 못했다.

발표에서는 “실제 데이터”라는 수준을 넘어 데이터별 출처를 구분해 설명한다. RFP는 원문 사실 검색, 회사 공개자료는 사전 역량 참고, 나라장터 낙찰자료는 과거 시장 패턴 참고에 사용한다.

## 데이터 활용 및 보호 기준

- RAG의 1차 근거는 원본 RFP·공고문과 출처가 연결된 회사 공개자료로 한다.
- 낙찰 JSON은 사업명·발주기관·낙찰자·날짜 등의 구조화 필드 조건 검색에 사용한다. 모든 항목을 문서 임베딩으로 처리할 필요는 없다.
- 기존 AI 보고서와 중간 산출물은 결과 비교·오류 시나리오로 분리하고, 원문 사실의 증거로 검색하지 않는다.
- 같은 공고의 공고문·RFP가 여러 버전이면 공고번호·차수·첨부명·수집일을 메타데이터로 보존한다. 재공고/정정 공고 간 버전이 다른 경우 두 문서를 섞어 하나의 근거처럼 인용하지 않고 불일치로 노출한다.
- 담당자 이름·연락처처럼 검토 판단에 불필요한 개인정보는 색인·시연 화면에서 제외하거나 가린다. 원본 PDF는 보존하고, 필요 시 비식별 사본을 별도 생성한다.
- 회사 공개자료·보도자료는 사전 검토 근거다. 입찰 자격·실적·인증·인력의 최종 충족 증빙으로 취급하지 않는다.
- 낙찰 데이터는 “수주한 기록”이라는 편향을 가지므로, 이를 입찰 참여 여부의 정답 라벨로 설명하지 않는다.

## 참고할 버전 확인 사항

로컬 공고 기록상 CDW 사업은 재공고이고 첨부 파일명이 “제안요청서 수정”으로 표시된다. 세 입력 PDF가 모두 원본이라는 사용자 확인은 반영했으나, 이 입력본이 해당 재공고의 최신 수정 첨부와 동일한 판본인지 파일 비교는 하지 않았다. 구현에서는 판본 불일치를 무시하지 않고 별도 문서 버전으로 처리한다.
