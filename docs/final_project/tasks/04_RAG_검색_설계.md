# Task 04 — 핵심정보 검증 RAG 검색 설계

상태: 설계 완료  
작성일: 2026-11-11

## 목표와 RAG가 필요한 이유

T1이 추출한 금액·참가자격·기간이 실제로 PDF 어디에, 어떤 문맥과 조건으로 적혀 있는지 찾아 T1.5 검증에 제공한다. 정답 문구를 프롬프트에 미리 넣는 방식으로는 새 RFP의 페이지·표·예외 조항을 확인할 수 없다. RAG 검색은 **검증 대상 주장에 맞는 원문 근거를 찾고 페이지 인용을 붙여 후속 대조를 가능하게 하는 단계**다.

RAG가 의미하는 것은 검색 결과의 사용이다. 관련 페이지를 검색하고, 해당 구간을 검증 입력에 넣으며, 검증 결과와 함께 문서·페이지·인용문을 보존한다. 검색 유사도만으로 정확성을 판단하지 않는다.

## 코퍼스 범위

### 검증 T1.5의 주 코퍼스

- 사용자가 원본이라고 확인한 `data/input`의 RFP PDF 3건
- 같은 사업의 나라장터 공고문 및 제안요청서 첨부. 로컬 `outputs/notices/notices.json`에서 세 입력 건에 대응하는 공고 레코드/첨부 링크를 찾았다.
- 공고번호·차수·첨부파일명·수집일·정정/재공고 관계를 문서 버전 메타데이터로 보존한다.
- CDW 건은 로컬 공고 레코드가 재공고이며 첨부명에 수정 RFP라고 표기되어 있다. `data/input` PDF와 첨부 파일의 내용/판본은 동일하다고 가정하지 않는다. 버전이 다르면 각각의 출처로 인덱싱하고 차이를 보류 상태로 드러낸다.

### T1.5 코퍼스에 섞지 않는 자료

- 기존 AI 분석 JSON/Markdown과 최종 보고서는 T1이 만든 결과물이므로 사실 검증 검색의 증거 코퍼스에서 제외한다.
- 회사 공개자료는 기존 T2가 역량 대조에 사용할 수 있지만, T1.5가 RFP 조건을 검증할 때는 증거로 사용하지 않는다.
- 나라장터 낙찰 이력은 T3 시장 조사 자료다. 금액·참가자격·일정의 RFP 원문 근거를 대신하지 않는다.

## 문서 처리와 인덱싱

### 추출 및 원문 보존

- 기존 pypdf/pdfplumber 기반 페이지 분석을 재사용해 PDF 텍스트와 표를 추출한다.
- 각 페이지의 추출 상태를 기록한다. 텍스트가 부족하거나 표 구조가 깨진 페이지는 OCR/수기 확인 후보로 남긴다.
- 발표·색인에 필요하지 않은 담당자 연락처 등 개인정보는 검색 텍스트에서 제외하거나 마스킹한다. 원본 PDF는 수정하지 않고 보존한다.

### 분할 단위

- 우선 제목·번호가 붙은 조항 또는 의미가 완결된 문단 단위로 나눈다.
- 표는 행을 레이블·열 제목과 함께 보존하고, 여러 행에 걸친 머리글 관계도 연결한다.
- 조항이 페이지를 넘어가면 문맥을 이어 주되, 인용 가능한 개별 페이지 범위도 남긴다.
- 고정 글자 수로 무조건 자르지 않는다. 실제 검색 사례를 평가해 chunk 경계를 조정한다.
- “참가자격”처럼 누락 여부가 중요한 항목은 개별 검색 chunk와 별도로 해당 제목 구간 전체를 열람할 수 있게 parent-section 관계를 저장한다.

### 메타데이터

각 chunk에 최소 다음 정보를 붙인다.

- 사업/공고 ID, 공고번호와 차수
- 원본 파일명, 파일 해시, 출처 URL, 수집/개정 날짜, 문서 유형(RFP/공고/정정/재공고)
- 페이지 번호, 섹션 경로, 조항 번호, 표/행 정보
- 추출 품질(OCR 필요, 표 파싱 실패 등), 개인정보 마스킹 여부

이 메타데이터로 사업과 판본을 먼저 제한하고, 잘못된 공고의 유사 문구가 근거로 섞이지 않게 한다.

## 검색 전략

검색은 범주별 질의 템플릿을 쓴다. exact keyword 검색은 법률·조항의 핵심 표현을 놓치지 않는 데, 의미 검색은 다른 말로 쓰인 조건을 찾는 데 사용한다. 결과를 병합할 때는 같은 원문 구간의 중복을 합치되 서로 다른 판본은 합치지 않는다.

| 검증 범주 | 검색 질의에 포함할 정보 | 검색 결과를 검증에 쓰는 방식 |
|---|---|---|
| 사업금액 | 추출 숫자·단위, `사업예산/사업금액/총사업비/추정가격/기초금액`, VAT, 연차·계약기간 | 수치가 붙은 레이블·표 행과 주변 설명을 검색해 금액 의미·범위·세금 조건을 대조하고 다른 금액 후보를 모음 |
| 참가자격 | `입찰참가자격`, 면허·등록·실적, 기업규모 제한, 공동수급·지역·하도급, 예외 문구 | 세부 조건뿐 아니라 적용 주체·단서·예외를 포함한 조항을 가져옴. 목차·제목 탐색 결과와 함께 자격 관련 구간의 완전성을 검토 |
| 기간·기한 | `계약기간`, 착수·준공, 제안서·입찰서 마감, 공동수급 협정 제출, 추출된 날짜/기간 | 날짜 주변 레이블과 표 열을 함께 찾아 일정 종류를 대조하고 상대기간·절대 날짜·시각을 구분 |

## T1.5에 전달할 근거 형식

검색 근거는 단순한 텍스트 덩어리 대신 다음 필드를 가진 레코드로 넘긴다.

```json
{
  "document_id": "공고번호-차수-첨부ID",
  "document_type": "RFP 또는 공고문",
  "revision": "공고번호·차수·정정관계",
  "page": 12,
  "section": "Ⅱ. 입찰 및 계약 > 입찰 참가 자격",
  "quote": "검증에 필요한 원문 인용 구간",
  "retrieval_query": "이 구간을 찾은 범주별 질의",
  "extraction_quality": "normal"
}
```

검증기는 T1 주장, 범주별 검사 항목, 검색된 인용 및 출처를 함께 받아 항목별 비교 결과를 낸다. 답변에는 인용문과 페이지가 빠지면 안 된다. 원문에서 확인되지 않은 값을 채워 넣지 않는다.

## 재검색 조건과 종료

1. 첫 검색은 T1의 유형·값·주변 레이블을 포함해 수행한다.
2. 근거가 없거나 핵심 조건이 빠졌으면 동의어/조항 유형을 확장하고, 부모 섹션·이웃 페이지를 추가 검색한다.
3. 해당 공고의 판본을 다시 확인한다. 특히 차수 변경·재공고·수정 첨부를 검토한다.
4. 검색을 한 번 보강한 뒤에도 근거가 없거나 원문이 서로 충돌하면 반복을 멈추고 `human_review` 또는 `conflict`로 끝낸다.

검색 횟수·결과 수 임계값은 실제 평가 사례를 보고 조정한다. 검색 점수 임계값 하나만으로 “충분한 근거”를 선언하지 않는다.

## 참가자격의 누락 검출

검색은 관련 조항을 찾는 데 유용하지만, 검색 결과에 나타나지 않은 조건이 문서에 없다고 보증하지 않는다. 그러므로 참가자격은 다음을 함께 사용한다.

- PDF 전체의 목차/제목/번호 구조에서 참가자격과 연결된 모든 조항·부록 위치를 열거한다.
- 해당 범주 키워드 검색으로 다른 장의 교차 참조와 단서 표현을 추가 탐색한다.
- 탐색한 페이지/섹션 목록과 처리 상태를 기록한다. 추출 실패 페이지가 남으면 완전성 통과를 금지한다.
- 검증 결과에는 “문서 범위 전체를 확인함” 또는 “다음 구간을 아직 확인하지 못함”을 명시한다.

## 품질 평가

범주별로 별도 측정한다.

- **Evidence Recall:** 정답 근거 페이지/조항이 검색 후보에 포함되는가
- **Citation correctness:** 인용문이 실제 페이지에 있고 해당 주장을 지지하는가
- **Field correctness:** 유형·값·조건이 기대 결과와 맞는가
- **Completeness:** 문서의 필수 자격 조건, 금액 조건, 일정 항목을 누락하지 않았는가
- **Unsafe auto-pass:** 근거 부족·충돌인데 통과로 판정한 비율

정상, 누락, 충돌, 문맥 오인, 표/OCR 손상, 공고 버전 차이 사례를 세 범주 각각에 준비한다. 전체 평균만 보고하지 않고 금액·자격·기간별 수치를 따로 제시한다.

## 기술 구성 제안

- **LangGraph:** 검색·검증·재검색·Human Review 라우팅을 제어한다. (Task 05에서 State/Edge로 구체화)
- **LlamaIndex:** 수업에서 다룰 RAG 도구로 문서 연결·검색 계층을 구성하는 후보로 둔다.
- **검색:** 한국어 법률/입찰 표현을 위해 키워드 검색과 임베딩 기반 검색을 함께 쓰는 혼합 검색을 우선 검토한다.
- **저장:** 현재 데이터가 소규모이므로 로컬 영속 벡터 저장소로 시작하되, 정확한 라이브러리/버전은 구현 시 공식 문서를 확인하고 dependency를 고정한다.
- **기존 코드 재사용:** PDF 페이지·표 추출과 품질 표시를 재사용하고, 기존 AI 보고서는 검색 코퍼스에서 분리한다.

이 제안은 아키텍처 초안이다. 검색 구현에 사용할 정확한 저장소/패키지 버전은 코드 작성 전에 공식 문서를 기준으로 확인한다.
