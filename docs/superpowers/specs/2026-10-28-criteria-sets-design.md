# 판단 기준 세트 — 설계

2026-10-28 · 사용자 승인한 기본안(대화) 정리

## 왜

판단 기준(공고 필터 + Go/No-Go 체크리스트)이 YAML 하나로 고정돼 있다. 사업 전략에 따라 "40억 → 20억", "핵심 기관 추가"처럼 기준을 바꿔 보고 싶을 때 YAML을 고치면 기본값이 사라진다. 기존 기준은 기본으로 남기고, 이름 붙인 기준 세트를 추가해 두었다가 다시 쓴다.

## 목표

- **"기본" 세트** = 지금 `config/notice_filter.yaml` + `config/checklist.yaml`. 화면에서 고치거나 지울 수 없다.
- 사용자 세트: 기본(또는 다른 세트)을 복제 → 이름 → 값 수정 → 저장. 다음 실행에도 남는다.
- **적용 세트는 하나.** 지금 수집(공고 필터)과 새 검토(체크리스트)가 적용 세트로 판정한다.
- 공고와 검토 건에 어느 세트로 판정했는지 남기고 보여준다.

## 비목표

- 체크리스트 항목(K1~K4, S1~S5) 추가·삭제·문구 수정 — 평가 로직이 항목별 코드라 범위 밖.
- 세트 버전 이력, 세트 간 비교 화면.
- 기존 공고·보고서 일괄 재판정.

## 고칠 수 있는 값

| 구분 | 키 | 형식 |
|---|---|---|
| 공고 필터 | `min_amount_krw` | 0 이상 정수(원), 화면은 억 단위 입력 |
| | `deadline_warn_days` | 0~30 정수 |
| | `field_keywords` | 문자열 목록 |
| | `exclude_contract_terms`, `confirm_contract_terms` | 문자열 목록 |
| 체크리스트 | S2 `keywords` 2점 / 1점 | 문자열 목록 |
| | S3 `core_agencies` | 문자열 목록 |
| | `decision.go`, `decision.review` | 0~10 정수, review < go |

나머지(`ict_classes`, `confirm_flags`, `collect_keywords`, `default_days`, 항목 문구)는 기본 세트 값을 그대로 쓴다.

## 저장

- `outputs/criteria/sets/<이름>.json` = `{name, created_at, updated_at, values}` (`values`는 위 표의 값만).
- `outputs/criteria/active.json` = `{name}`. 없거나 가리키는 세트가 없으면 "기본".
- 세트 이름: 앞뒤 공백 제거 후 1~30자, `/ \ :` 와 `.`으로 시작 금지, "기본" 금지. NFC 정규화.
- 판정 시 실제 설정 = 기본 YAML에 `values`를 덮어쓴 결과.

## 이미 판정한 건 고정

- **공고:** 수집 때 `judged.criteria_set`에 세트 이름 기록. 다시 수집하면 그때 적용 세트로 다시 판정(지금과 같음).
- **검토 건:** 체크리스트는 보고서를 열 때마다 계산되므로, 검토 시작·다시 실행 때 적용 세트의 체크리스트 설정을 건 폴더 `criteria.json`(`{name, checklist}`)에 스냅샷한다. 결과 화면은 스냅샷이 있으면 그것으로, 없으면(CLI·기존 건) 기본으로 평가한다.

## 권한 (X-Role, 시연용)

| 동작 | 담당자 | 본부장 |
|---|---|---|
| 세트 보기 | ✓ | ✓ |
| 세트 만들기·고치기·지우기 | ✓ | ✓ |
| 적용 세트 바꾸기 | | ✓ |

적용 중인 세트는 지울 수 없다(409). 기본 세트 쓰기·지우기는 400.

## API

- `GET /api/criteria?set=<이름>` — 기존 응답 + `sets`(목록), `active`, `selected`. `notice_filter`·`checklist`는 `selected`(기본: 적용 세트)의 병합 결과.
- `PUT /api/criteria/sets/{name}` `{values}` — 만들기/고치기.
- `DELETE /api/criteria/sets/{name}`
- `PUT /api/criteria/active` `{name}` — 본부장만.

## 화면 (판단 기준 메뉴)

- 머리 아래 세트 칩: `[기본] [세트…] [＋ 새 기준]`, 적용 중인 세트에 "적용 중" 표시.
- 선택한 세트를 지금 화면 형식으로 보여준다(같은 컴포넌트).
- 사용자 세트: [편집] [삭제] [이 기준 적용](본부장만). 기본: 보기만, [복제해서 새 기준].
- 편집 패널: 위 표의 값. 목록은 쉼표로 구분한 입력칸.
- 공고함 정보 상자: "기준 세트" 항목 추가. 결과 화면 체크리스트 탭: "판단 기준: <이름>".

## 빌더 재량

컴포넌트 분리, 문구, 입력칸 배치.

## 내가 정한 것 (사용자 확인 전 판단)

- 스냅샷 위치를 건 폴더 `criteria.json`으로 함(보고서별 사이드카보다 단순, 다시 실행하면 새 기준으로 덮어씀).
- 다른 세트에서 복제도 허용(기본에서만이 아니라).
